# 라넬 PySide6 비공개 앱 — 무료 배포 체크리스트

작성일: 2026-10-19 · 대상: Windows의 PySide6 + Qt Widgets 운영 앱 → EC2 FastAPI

**선택 확정 — 2026-10-19:** 사용자가 LGPL로 진행하기로 결정했다. PySide6·Qt Widgets의 해당 구성요소에 LGPLv3를 적용하고 앱 고유 소스는 비공개로 유지한다. 현재는 기업 요청 프로토타입 단계다. 아래 미완료 항목은 이 선택을 구현·검증하는 작업이며, 상용 라이선스와의 재선택을 요구하는 목록이 아니다.

목표는 앱 고유 소스를 비공개로 유지하면서 LGPLv3 조건으로 라이브러리를 이용하는 것이다. Qt는 LGPL 요건을 모두 충족하면 앱 소스를 비공개로 유지할 수 있다고 안내한다. 이 문서는 배포 준비 기준이며, 아직 실제 앱·설치본의 준수를 검증한 결과가 아니다. [Qt 공식 안내][qt-lgpl]

**권장 배포안:** 교체 가능한 라이브러리를 별도 파일로 두는 폴더형 앱과, 배포 버전에 대응하는 오픈소스 소스 묶음을 함께 제공한다. 구현 후보는 `PyInstaller --onedir`다. 패키저·버전·설치 프로그램은 아직 확정하지 않는다. 한 파일짜리 설치 프로그램이 설치 후 폴더를 풀어 놓는 방식도 이 구조로 만들 수 있다.

체크 항목의 **의무**는 해당 LGPL 배포 경로에서 충족할 요건, **검증**은 그 요건을 실제 산출물로 확인하는 작업, **권장**은 이번 프로젝트에 제안하는 구현 방식이다. **정책**은 라넬·멘토와 별도로 확인할 내용이다.

## 1. 적용 범위와 배포 책임

- [x] **결정:** PySide6 + Qt Widgets를 LGPLv3 조건으로 이용한다. 2026-10-19 사용자의 명시적 선택을 기록했다. 앱 전체의 라이선스를 LGPL로 바꾸는 결정이 아니다.
- [ ] **정책 정합성:** GitLab의 [AGENTS.md](../../AGENTS.md)와 [THIRD_PARTY.md](../THIRD_PARTY.md)에 GPL 계열 제한이 명시돼 있음을 확인했다. LGPL 선택과 저장소 규칙의 적용 범위·예외를 정리한다. 사용자의 기술 선택을 회사의 공식 예외 승인으로 기록하지 않는다.
- [ ] **정책:** 실제 배포 주체, 앱 수령자, 소스 제공·업데이트 담당자를 정한다. 라넬에 설치본을 전달하는 경우도 배포 조건 검토에 포함한다.
- [ ] **정책:** 별도의 과제·납품 계약에 앱 소스 인도 조건이 있는지 확인한다. LGPL이 허용하는 비공개 유지와 계약상 인도 의무는 각각 검토한다.

현재 코드와 목표 설계의 차이 및 저장소 규칙은 [아키텍처 안내](./README.md)에 정리했다.

## 2. 포함할 라이브러리와 버전 확정

- [ ] **검증:** Python·PySide6·Shiboken6·Qt·패키저·설치 도구의 실제 버전을 고정한다. 설치 패키지 이름만 보지 말고 최종 DLL·`.pyd`·플러그인·Python 모듈 목록도 수집한다.
- [ ] **의무:** 포함하는 각 구성요소의 적용 라이선스·저작권·예외 조항·수정 여부를 확인한다. LGPL을 선택할 수 있는 부분에 그 조건을 적용하고 제3자 라이선스를 보존한다.
- [ ] **권장:** 처음에는 필요한 Qt Core·Gui·Widgets 중심으로 구성한다. `pyside6` 메타 패키지는 Essentials뿐 아니라 Addons도 설치하므로, 설치됐다는 이유로 모든 모듈을 앱에 복사하지 않는다.
- [ ] **검증:** Qt Charts 같은 추가 모듈은 별도 검토한다. 예를 들어 Qt Charts 6.10은 GPLv3 또는 상용 경로이므로, Widgets의 LGPL 선택지를 그대로 적용하면 안 된다.
- [ ] **검증:** 영상 미리보기·전처리를 추가하면 Qt Multimedia·FFmpeg·코덱 등 실제 포함 바이너리의 라이선스와 빌드 옵션을 재검토한다. 이미지 플러그인·폰트·아이콘·네트워크 의존성도 목록에서 누락하지 않는다.
- [ ] **권장:** `third-party-manifest.csv`에 `구성요소 / 버전 / 실제 파일 경로 / 적용 라이선스 / 저작권 / 원본 출처 / 소스 묶음 / 수정 여부 / SHA-256`을 기록한다. 해시는 매칭 근거이며 소스 제공을 대신하지 않는다.

근거: [PySide6 패키지 구성][qt-packages], [Qt Widgets 라이선스][qt-widgets], [Qt Charts 6.10][qt-charts], [Qt 제3자 라이선스 안내][qt-licensing], [FFmpeg 법적 안내][ffmpeg].

## 3. 앱 소스와 라이브러리를 분리해 패키징

이번 권장안은 LGPLv3 4(d)(1)의 호환 라이브러리 교체가 가능한 공유 라이브러리 방식을 목표로 한다. 다른 재결합 방식을 선택하면 제공해야 할 자료가 달라질 수 있으므로 다시 검토한다. [LGPLv3 4절][lgpl]

- [ ] **권장:** 먼저 폴더형 배포로 구성한다. `--onefile`을 택하려면 실행 때 임시로 푸는 내부 복사본까지 포함해 교체·재결합 경로를 별도로 마련한다. 단일 EXE 자체를 자동 위반으로 판단하지는 않는다.
- [ ] **검증:** Qt DLL뿐 아니라 PySide6 바인딩 `.pyd`, Shiboken 런타임, 사용 중인 Qt 플러그인도 호환되는 수정본으로 교체할 수 있게 한다. 파일의 실제 위치와 탐색 경로를 문서화한다.
- [ ] **검증:** LGPL 적용 Python 파일이 교체 불가능한 내장 아카이브에 남지 않는지 확인한다. PyInstaller의 기본 Python 수집은 내장 PYZ이므로 `--onedir`만으로 끝났다고 보지 않는다.
- [ ] **권장:** 필요한 LGPL 패키지의 Python 부분만 외부 `.py`로 수집하도록 hook의 `module_collection_mode` 등을 검토한다. 우리 앱 고유 코드를 전부 외부 `.py`로 풀어야 한다는 뜻은 아니다. 외부 파일이 실제 import에 사용되는지 확인한다.
- [ ] **검증:** 서명·해시 검사·복구 기능이 수정 라이브러리 실행을 무조건 차단하거나 매 실행마다 원본으로 되돌리지 않게 한다. 서명된 설치본 제공과 서버 인증은 유지하되, 사용자가 수정본을 실행할 경로를 확보한다.
- [ ] **권장:** 사용자의 설치 폴더 또는 관리자가 교체할 수 있는 설치 구조를 사용한다. 교체를 위해 모든 사용자에게 시스템 폴더 쓰기 권한을 주지는 않는다.

PyInstaller는 GPLv2에 예외가 붙은 도구다. 공식 안내는 의존성 조건을 지키는 범위에서 생성한 앱에 원하는 라이선스를 적용할 수 있다고 설명한다. **도구 자체를 수정·배포하는 경우와 우리 앱을 패키징하는 경우를 구분한다.** 라넬 정책이 GPL 개발 도구 사용 자체까지 제한한다면 이 예외를 포함해 확인한다. [PyInstaller 라이선스][pyinstaller-license]

위 패키징 방법은 구현 권고다. [폴더형·단일 파일 동작][pyinstaller-mode], [모듈 수집 설정][pyinstaller-hooks], [실제 import 순서][pyinstaller-advanced]를 기준으로 적용 버전에서 검증한다. 폴더형이라는 이름만으로 준수를 인증하지 않는다.

## 4. 실제 배포 버전의 라이브러리 소스 제공

- [ ] **의무:** 배포한 LGPL 라이브러리에 대응하는 완전한 소스를 확보한다. 수정하지 않은 라이브러리도 대상이다. 바이너리 wheel·DLL 파일만 전달하는 것은 소스 제공이 아니다.
- [ ] **검증:** PySide6·Shiboken·실제 Qt 모듈의 소스 버전/커밋을 배포 바이너리에 대응시킨다. 필요한 하위 저장소·포함 소스·패치가 빠지지 않았는지 확인한다.
- [ ] **의무:** 라이브러리를 수정했다면 수정된 소스, 변경 사실·일자와 필요한 고지를 포함한다. 필요한 빌드·설치 스크립트 및 설정도 대응 소스 범위에 맞게 제공한다.
- [ ] **권장:** 앱 다운로드 위치에 같은 릴리즈의 `third-party-sources.zip`을 추가 비용 없이 제공한다. 오프라인 납품은 동일 납품 매체에 소스 묶음을 함께 둔다. 막연한 ‘요청 시 제공’보다 실제 소스를 함께 제공하는 방식을 우선한다.
- [ ] **의무:** 온라인 제공 방식을 쓰면 바이너리 옆에 정확한 소스 위치를 안내하고 필요한 기간 접근을 유지한다. 일반 홈페이지나 움직이는 최신 브랜치 링크만 남겨 두지 않는다. 외부 서버를 이용해도 대응 소스의 가용성 책임이 없어지지 않는다.
- [ ] **검증:** 수령자의 권한으로 소스 다운로드·압축 해제·버전 매칭을 확인한다. LGPL 소스에 재배포 금지 NDA 같은 추가 제한을 적용하지 않는다.

GPLv3 6(d)는 다운로드 방식의 대응 소스 접근을, 6(a)는 물리 매체 동봉을 다룬다. 서면 제공 약속을 선택할 경우에는 전달 방식과 6(b)의 최소 3년 등 요건을 별도로 충족해야 한다. **모든 배포가 무조건 3년 보관이라는 식으로 기간을 통일하지 않는다.** [GPLv3 1·5·6절][gpl] · [Qt 소스 제공 안내][qt-lgpl]

이 경로에서 제공하는 것은 해당 라이브러리의 대응 소스와 필요한 자료다. 앱 고유 저장소 전체를 공개하는 방식으로 바꿀 필요는 없다. 실제 소스 묶음에 들어갈 파일을 배포 manifest와 대조한다.

## 5. 고지문과 앱 이용약관

- [ ] **의무:** 배포본에 GPLv3와 LGPLv3 원문 사본, 실제 사용 라이브러리의 저작권·라이선스 고지를 포함한다. 번역 요약문만 넣지 않는다.
- [ ] **의무:** 각 앱 복사본에서 LGPL 라이브러리를 사용한다는 점과 적용 라이선스를 알 수 있게 한다. 실행 중 저작권 정보를 표시한다면 라이브러리 저작권과 원문 위치도 함께 표시한다.
- [ ] **권장:** 앱의 `도움말 → 오픈소스 라이선스`에서 고지·버전·소스 위치·교체 안내를 열 수 있게 한다. 설치 폴더에도 같은 자료를 둔다.
- [ ] **의무:** 앱 이용약관·납품 조건의 수정 및 역공학 금지 문구가 LGPL 부분의 수정과 그 수정을 디버깅하기 위한 역공학을 막지 않게 한다. 라이브러리에 대한 수령자의 권리도 보존한다.
- [ ] **검증:** 장비와 묶어 전달한다면 LGPLv3 4(e)와 GPLv3 6의 설치 정보 의무 적용 여부를 확인한다. 단순히 ‘전시용’이라는 이름만으로 면제 또는 적용을 단정하지 않는다.

근거: [LGPLv3 4(a)~(e)][lgpl], [GPLv3 6·10절][gpl]. 아래는 고지의 초안이며, 실제 버전·저작권·경로를 채운 후 원문과 함께 사용한다.

```text
이 제품은 PySide6, Shiboken6 및 Qt의 아래 구성요소를 사용합니다.
구성요소·버전·저작권·적용 라이선스: third-party-manifest.csv 및 licenses/ 참조
LGPL 적용 구성요소: GNU Lesser General Public License version 3
라이선스 원문: licenses/LGPL-3.0.txt, licenses/GPL-3.0.txt
해당 버전의 대응 소스와 변경 내역: SOURCE_CODE.md에 기재한 위치
호환 라이브러리 교체와 실행 방법: REPLACING_QT.md
제3자 구성요소에는 각각의 라이선스가 적용됩니다.
```

앱 이용약관에는 다음 취지를 반영한다. 최종 계약 문구는 납품 조건과 함께 검토한다.

```text
본 이용약관의 제한은 제3자 오픈소스 라이선스가 부여하는 권리를 제한하지
않습니다. LGPL 적용 부분의 수정과 그 수정을 디버깅하기 위해 해당
라이선스가 허용하는 역공학은 본 약관의 금지 대상에서 제외됩니다.
```

## 6. 라이브러리 교체와 재실행을 실제로 검사

다음은 공유 라이브러리 교체 조건을 확인하기 위한 프로젝트 검증 절차다. 아무 버전의 DLL이나 넣어 동작해야 한다는 뜻은 아니며, 인터페이스·아키텍처·의존성이 호환되는 수정본으로 검사한다.

- [ ] **검증:** 개발 환경이 없는 Windows 테스트 환경에 최종 설치본을 설치하고 정상 실행을 기록한다. 개발 PC의 Qt 경로를 우연히 참조하지 않는지 확인한다.
- [ ] **검증:** 제공한 소스·설명으로 인터페이스를 유지한 수정 라이브러리 시험본을 준비한다. 식별용 로그 등 작은 변경으로 원본과 구분한다. 앱 고유 소스나 회사 전용 서명 키 없이 교체·실행할 수 있는지 확인한다.
- [ ] **검증:** 앱을 닫고 기존 폴더를 백업한 뒤, 문서에 적힌 DLL·`.pyd`·플러그인·Python 파일 중 해당되는 파일을 호환 세트로 교체한다. 앱 본체를 다시 빌드하지 않는 이번 배포 경로가 실제로 성립하는지 확인한다.
- [ ] **검증:** 실제 로드 경로와 수정본의 표식을 확인하고 기본 화면·표·버튼·API 통신을 검사한다. 단순히 파일 복사가 성공했거나 다른 공식 버전이 실행됐다는 결과만으로 모든 교체 조건을 검증했다고 처리하지 않는다.
- [ ] **검증:** 재실행·복구·업데이트 기능을 확인한다. 수정본을 사용할 수 있는 절차가 보존되는지, 업데이트 후 바뀐 버전의 소스·고지·교체 안내가 함께 제공되는지 검사한다.
- [ ] **권장:** 앱 버전·패키저 버전·원본/수정 라이브러리 식별자·로드 경로·검사 결과를 릴리즈 기록에 남긴다. 실제 실행하지 않은 항목은 미검증으로 둔다.

`REPLACING_QT.md`에는 최소한 종료·백업 방법, 실제 파일 위치, 호환 조건, 빌드/교체 순서, 실행·로드 확인, 복원 방법을 적는다. PyInstaller의 내장 모듈이 외부 파일보다 먼저 로드될 수 있으므로 Python 부분도 확인한다. [LGPL의 호환 수정본 요건][lgpl] · [PyInstaller import 순서][pyinstaller-advanced]

## 7. 배포 묶음과 업데이트 관리

아래 파일명과 폴더는 제안이다. `_internal` 안의 실제 배치는 패키징 결과에 맞춰 기록한다.

```text
RanelOperator-<앱버전>-delivery/
├─ app/
│  ├─ RanelOperator.exe
│  ├─ _internal/                 # 교체 가능한 라이브러리와 런타임
│  ├─ licenses/                  # GPL·LGPL 원문 및 실제 제3자 고지
│  ├─ OPEN_SOURCE_NOTICES.txt
│  ├─ third-party-manifest.csv
│  ├─ SOURCE_CODE.md             # 대응 소스의 정확한 위치와 버전
│  └─ REPLACING_QT.md
└─ third-party-sources/
   ├─ 원본·수정 라이브러리 소스 압축파일
   ├─ patches/                   # 수정한 경우
   └─ BUILDING.md                # 필요한 빌드 설정·스크립트·절차 안내
```

- [ ] **권장:** 설치 프로그램과 ZIP 중 무엇을 쓰더라도 설치 후 고지·소스 안내·교체 안내에 접근할 수 있게 한다. 인터넷이 없는 전시 환경은 고지와 소스 묶음을 함께 전달한다.
- [ ] **검증:** 매 릴리즈마다 앱 바이너리·라이브러리 파일 목록·소스 묶음·고지·교체 안내가 같은 버전을 가리키는지 확인한다. 의존성을 올렸는데 소스 링크만 이전 버전으로 남지 않게 한다.
- [ ] **권장:** 배포 장소가 바뀌거나 과제 EC2가 종료돼도 필요한 소스 제공을 유지할 담당자와 저장 위치를 정한다. 수령자가 접근할 수 없는 팀 내부 Git 링크만 안내하지 않는다.
- [ ] **검증:** 앱 고유 소스, 개발용 `.env`, 인증 키가 실수로 배포 묶음에 들어가지 않았는지 검사한다. 제공해야 할 오픈소스 소스까지 일괄 삭제하지 않는다.

PyInstaller로 `.py` 원본을 넣지 않아도 Python 바이트코드는 복원·분석될 수 있다. **라이선스상 비공개 유지와 기술적으로 분석 불가능한 배포는 다르다.** 핵심 서버 로직과 공급자 키는 기존 설계대로 FastAPI 측에서 관리한다. [PyInstaller의 소스 보호 설명][pyinstaller-mode]

**출시 시 기록할 판정**

| 판정 항목 | 현재 상태 | 완료 근거에 적을 내용 |
|---|---|---|
| PySide6·Qt Widgets 이용 경로 | **LGPLv3 선택 확정** | 2026-10-19 사용자 결정; 앱 고유 소스 비공개 유지 |
| 저장소 규칙·회사 정책·계약 | 저장소의 GPL 계열 제한 확인; LGPL 선택의 예외·계약 정합성 미확인 | 적용 범위와 예외의 근거를 사용자 기술 선택과 구분해 기록 |
| 실제 버전·포함 모듈 | 미확정 | 라이브러리별 manifest와 라이선스 |
| 패키징 방식 | 폴더형 권장, 도구 미확정 | 패키징 설정과 최종 파일 목록 |
| 대응 소스와 고지 | 준비 전 | 수령자가 받은 경로·파일·버전 |
| 호환 수정 라이브러리 실행 | 미검증 | 최종 설치본의 교체 시험 기록 |
| 이용약관·장비 설치 조건 | 미검토 | LGPL 권리와 충돌하지 않는 조건 |

이 문서를 만들었다는 이유로 위 항목을 완료로 표시하지 않는다. 앱 전체 소스 공개를 피하려고 LGPL 구성요소의 소스 제공·교체 권리까지 제한하는 배포 방식은 선택하지 않는다.
