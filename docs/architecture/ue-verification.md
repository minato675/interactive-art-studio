# UE 작업물 검증 절차와 통과 기준

조립된 UE 작품이 전시(PC2)에 나가기 전에 정상 동작하는지 확인하는 절차입니다. [분산형 설계](./distributed-system-design.md) 9절(기술 검증)·10절(자동 검수와 재작업)의 UE 부분을 지금 구현 기준으로 적었습니다. Jira [S15P31A504-177](https://ssafy.atlassian.net/browse/S15P31A504-177).

- 코드: 정적 검사 `packages/studio/src/studio/verify/ue_contract.py`, PC1 실행 검증 `ue_runner.py`, 조립 `packages/studio/src/studio/assembly/ue_assemble.py` — 설명은 [verify README](../../packages/studio/src/studio/verify/README.md) · [assembly README](../../packages/studio/src/studio/assembly/README.md)
- 실행본: 라넬 공용 전시 맵(`RuntimeIntegrationProof`) Shipping. 전시와 **같은 실행본 · 같은 `release.json` 교체 경로**로 검증합니다.

## 순서

| 단계 | 하는 일 | 실패하면 |
|---|---|---|
| 1. 소재 검사 | `assets.json`이 가리키는 파일: 있는지, PNG 규칙 · 4096 이하 · 32MiB 이하, 맨 뒤가 아닌 층의 알파, 실루엣 기준 | 보류 — 소재 재생성(생성 쪽) |
| 2. 조립 | 명세 → 템플릿 선택(대응표) → 허용된 칸만 채움. 반응 캔버스 앞에 놓이는 층은 알파 필수, 불투명 30% 초과는 경고 | 보류 — 대응 없음 · 지원 안 하는 층/재질 값 |
| 3. 정적 검사 | 지금 runtime 계약(scene 표 · Look · GpuFlow 범위와 장면 입자 예산 · 조건) + 공용 카탈로그(패턴 · 객체) + 고정 무대 | 보류 — 재조립. 오프라인으로 알 수 없는 것은 '미검증'으로 남김 |
| 4. 사람 소재 검수(선택) | 운영 앱에서 소재 승인/반려([S15P31A504-171](https://ssafy.atlassian.net/browse/S15P31A504-171)) | 반려 — 새 소재 삭제, 지금 작품 유지 |
| 5. PC1 실행 검증 | 검수 폴더(`data_dir/review/delivery`)에 게시 → PC1 Shipping이 적용 → 합성 손으로 반응 · 성능 판정(아래) | 보류 — 리포트 남기고 지금 작품 유지 |
| 6. 사람 최종 검수(선택) | 같은 검수 폴더의 화면을 PC1에서 보고 승인/반려 | 반려 — 전시 폴더는 건드리지 않음 |
| 7. 게시 | 검증한 **같은 파일**을 전시 폴더에 게시(새 버전 폴더 + `release.json` 원자 교체) | 게시 실패 — 지금 작품 유지 |

사람 검수는 기본 꺼짐입니다(설계 10절 "자동 검수 통과를 기본 게시 승인으로"). 켜져 있으면 5단계를 통과한 뒤에만 사람이 봅니다 — 자동 검증이 잡는 기술 결함을 사람이 다시 보지 않도록.

## PC1 실행 검증 통과 기준 (`ue_runner.Thresholds` 기본값, 규칙 버전 `ue-runner-v6`)

| 판정 | 기준 | 근거 |
|---|---|---|
| 적용 | 이번 프로세스(PID)의 이 버전 결과가 `Applied`, `ActiveReleaseVersion` 일치, `Error` 없음, 35초 안 | runtime `release.json.status.json` |
| 준비 | `PrepareSeconds` ≤ 10초, `PreparedBytes` ≤ 1024MB | 교체 중 끊김 방지 |
| 빈 화면 아님 | 입력 전 화면 밝기 편차 > 0.5 | 검정 · 단색 화면 거부 |
| 손 반응 | 손 궤적 주변에서 (입력 중 변화 − 평소 변화) ≥ 0.02. 평소 변화는 입력 없는 화면 3쌍 중 가장 큰 값. 평소 변화 > 0.1 이고 3쌍의 흔들림(최대 − 최소) ≥ 0.02이며 손이 장면 행동에 닿았으면 미달이어도 fail 대신 사람 확인(재는 값이 잡음보다 작음) | 루프 영상 · 유체처럼 원래 움직이는 장면도 손 반응만 본다. PC1 10/25 ripple_lake는 흔들림 0.032로 같은 번들이 실행마다 0.011~0.021을 오갔다. 돌아다니는 객체(`wander`)가 있는 장면은 객체가 손 주변 평소 변화를 키워 이 조건으로 사람 확인이 될 수 있다(객체 영역을 빼는 마스크는 범위 밖) |
| 장면 행동에 닿음 | Trace `BehaviorInputs.ActiveContacts` > 0 | 패킷 수신이 아니라 장면 조건까지 닿았는지 |
| 두 손 | 합성 손 2개를 모두 수신 | |
| 복귀 | 화면 반감기 2.5초 미만이거나 모르는 장면: 입력 뒤 손 주변 변화 ≤ 평소 변화 × 2 + 0.05 (복귀가 `stay`인 작품은 끔) | |
| 잔상 · 가라앉음 | 화면 반감기 2.5~12초 장면: 손 뗀 뒤 5초에 손 주변 변화 − 긴 평소 변화 ≥ 0.02(잔상), min(반감기 × 4, 20)초 뒤와 그 3.2초 뒤 사이 변화 ≤ 평소 변화 × 2 + 0.05 **또는** 5초 → 복귀 → 3.2초 뒤로 갈수록 평소 화면과의 평균 밝기 차이가 단계마다 평소 차이보다 크게 줄고, 전체로 0.005 이상 줄고, 끝이 5초 때의 0.8배 이하(가라앉음. 5초 화면이 없으면 앞 조건만). 12초 이상은 복귀를 보지 않음 | 진한 잔상은 20초 뒤에도 옅어지는 중이라 픽셀이 바뀐다(PC1 10/25: fluid 0.27 → 0.07 → 0.04, paint 0.047 → 0.036 → 0.031). 깜빡이는 장면은 어느 단계에서 다시 멀어져 실패. 물결 · 입자는 PC1 보정 전까지 사람 확인 |
| 긴 프레임 | 입력 구간 16.7ms 초과 프레임 ≤ 초당 6개 (저장분 + `DroppedLongFrames`) | 측정 전 GPU가 30% 넘게 바빴으면 '환경 의심' 표시 |
| 실행본 유지 | 검증 내내 같은 프로세스 | |

손 주변이 평소에도 절반 넘게 바뀌는 장면은 화면으로 가를 수 없어 손 반응 · 복귀를 화면으로 판정하지 않고 '장면 행동에 닿음'으로만 봅니다(리포트 `screen_judged=false`). 이런 장면과 평소 변화가 10%를 넘는 장면은 화면 판정을 믿기 어려워 `needs_review`(사유 `review_reasons`)가 붙습니다. 앞 층이 반응을 가리는 장면을 자동으로 통과시키지 않으려는 것입니다.

게시 판단은 `Report.verdict`로 합니다: `pass`(자동 통과) · `review`(규칙은 통과했지만 사람 최종 검수 필요) · `fail`(보류). `passed`만 보면 `review`가 검수 없이 게시됩니다.

리포트(`Report.summary()`)에는 판정별 값과 기준, `verdict`, 스크린샷(입력 전 · 평소 3장 · 손 · 입력 뒤) 경로, 측정값, 규칙 버전, 번들 해시(버전 폴더 파일 해시 목록), 카탈로그 버전, 측정 전 GPU 사용량이 남습니다.

## 자동 검증과 사람 검수의 범위

| 자동 검증이 본다 | 사람이 본다 |
|---|---|
| 계약 · 카탈로그 · 무대 위반, 적용 실패, 반응 없음, 복귀 없음, 끊김, 빈 화면 | 주제 · 분위기와 맞는지, 작품으로서 아름다운지, 앞 층이 반응을 얼마나 가려도 되는지 |

AI 판정(주제 · 스타일 일치 등)은 [S15P31A504-184 검증 Agent](https://ssafy.atlassian.net/browse/S15P31A504-184)에서 정합니다. 붙이게 되면 5단계 뒤의 보조 판정(경고)으로 두고 규칙 판정을 대신하지 않습니다.

## 아직 정하지 않은 것 · PC1 실측이 필요한 것

- 캔버스 그림 입력(`SourceImage`)과 날갯짓 나비를 쓰는 장면은 10/25 실행본(`RuntimeIntegration1025`, 라넬 작업 폴더 9957d16 카탈로그) 이후에서만 적용된다. 러너는 실행본 카탈로그 버전을 기록만 하고 막지 않으므로, 이전 실행본으로 검증하면 적용 실패(fail)로 나온다. 실행본 교체와 조립기 반영을 같은 시점에 한다.

- 기준값(손 반응 0.02, 긴 프레임 초당 6개 등)은 시작값입니다. 실제 템플릿(유체 · 영상 · GPU 입자)의 평소 변화량과 PC1 프레임 시간을 재서 계열별로 다시 정합니다(설계 19절 계열별 검수 임계값).
- 합성 손 궤적은 화면 가운데 근처의 고정 경로입니다. 장면에 물결 범위(`SurfaceDeformation`의 `DropAreaMin/Max`, 그림 위 물결 템플릿)가 있으면 같은 모양의 궤적을 그 범위 안으로 옮기고 줄입니다(좌우 반전돼도 범위 안). 가운데 궤적은 아래쪽 물에 닿지 않아 PC1 10/25 시연에서 손 반응 실패가 났습니다. 그 밖에 조건 영역이 가장자리인 템플릿은 템플릿별 궤적이 필요합니다. 녹화한 관람객 입력 재생으로 바꾸는 것은 [S15P31A504-178](https://ssafy.atlassian.net/browse/S15P31A504-178)입니다.
- PC1이 central과 같은 PC라는 지금 구성 기준입니다. 제작 노드가 생기면 Node Agent가 같은 러너를 부릅니다.
