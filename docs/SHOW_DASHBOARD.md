# 시연 관리 대시보드

PySide6의 `시연 관리`는 다른 탭과 같은 밝은 테마를 사용한다. 현재 재생과 장비 상태를 먼저 표시하고 라이브러리·구성 타임라인·목록 편집은 접어서 보관한다.

## 운영 상태와 제어 (S15P31A504-235)

중앙 저장, PC2 동기화, UE 적용, 실제 재생을 각각 표시한다. 현재 작품과 구간 진행률은 신선한 보고·Applied 활성 버전 일치가 있어야 표시한다. 조회 실패·90초 이상 오래된 보고는 미확인이다. 앱이 시간을 임의로 증가시키지 않는다. 전체 진행률·종료 시각은 반복·전환 지연 근거가 없으면 미확인으로 둔다. 구성 타임라인은 저장 전 편집, 실행 목록은 중앙 저장 구성이다.

썸네일은 인증된 원본 이미지이며 실시간 송출 화면이 아니다. 작품별 캐시 보고가 없는 구형 키트에서는 총 캐시 개수만으로 개별 작품 준비 완료를 추측하지 않는다. PID·세션은 UE 보고, PC2 온라인은 Agent 보고이며 Controller·TD·센서 상태는 별도 보고가 없어 미확인이다.

자동 전환 시작/멈춤은 기존 autoplay 설정을 저장한다. 멈춤은 UE 영상 일시정지가 아니라 현재 화면 유지다. 현재 작품 재적용·다음 작품·운영자가 고른 복구 작품은 확인 후 자동 전환을 끄고 기존 게시 승인 API로 적용 요청한다. 승인자·사유가 필요하며 접수와 실제 적용을 구분한다. 미저장 편집은 먼저 저장하거나 다시 불러와야 한다.

UE 원격 실행·종료·재시작과 애니메이션 일시정지는 중앙 명령 계약이 없으므로 비활성화하고 이유를 표시한다. 기존 PC2 자동 복구는 그대로 유지한다. 아카이브 재생/정지는 별도 계약이다. PC2 설치·실제 화면·센서 검증은 UI 검증과 구분한다.

선택적인 추가 재생 보고(cached_verification_job_ids·cache_errors·current_repeat)는 갱신된 show_playback.py와 중앙 계약이 필요하다. 구형 보고도 허용하고 누락 필드는 미확인으로 남긴다.

**추가 구현:** PC2 시간 전환·오프라인 캐시 재생·업데이트 방법은 [실제 재생 연동](SHOW_PLAYBACK.md)을 따른다. 아래 851건 검증은 시간 옵션 저장 단계의 이전 기록이다.

## 사용할 수 있는 기능

- 등록된 시연 노드 선택, 현재 활성 작품·버전·보고 시각 확인. 실제 Applied 근거와 신선도는 피드백 API와 같은 기준이다.
- 실행 검수에 통과한 작품 목록과 원본 조립·검수 ID 확인. `review`는 명시적 사람 승인 이후만 후보이며 반려·실패·미리보기 예외 작품은 제외한다.
- 작품 선택 → 대상 노드·승인자·사유 확인 → 기존 게시 승인 API에 적용 요청. 작업 ID·Staged/Ready/Applied를 구분하고 완료 전 상영 성공으로 표시하지 않는다.
- 작품당 공통 시연 시간, 작품별 반복·사용 여부, 순서, 전체 반복을 중앙 DB에 저장·다시 불러오기. 처음은 빈 목록이다. 현재 조회한 작품을 사용자가 추가하며 가짜 작품을 주입하지 않는다.
- 시간·반복을 반영한 구성 타임라인. 이것은 저장할 계획의 시각화이며 실제 재생 위치/타임코드가 아니다.

## 작품당 시연 시간

기본값은 **2분(120초)**이며 모든 작품에 같은 시간을 적용한다. `시연 관리 → 중앙 재생 구성 → 작품당 시연 시간` 옵션에서 초 단위로 변경하고 `중앙에 구성 저장`을 누른다. 허용 범위는 기존 시간 입력과 같은 5~3600초다. `2분으로 복원`은 편집 값을 120초로 되돌리며 중앙 저장은 별도로 수행한다.

옵션을 변경하면 현재 편집 목록의 모든 작품과 이후 추가할 작품에 동일하게 반영한다. 작품 행의 시간은 읽기 전용이며 개별 시간 예외는 두지 않는다. 빈 목록에서도 옵션을 저장할 수 있고 앱 재시작·다시 조회 후 같은 값을 사용한다. 반복 3회는 120초짜리 상영 3회(총 360초)를 뜻한다. 전체 반복은 이 목록을 다시 순환하는 설정이다.

중앙 구성 JSON은 `plan.duration_seconds`에 공통 시간을 한 번만 저장한다. `plan.items`에는 검수 작업 ID·반복·사용 여부를 저장한다. 폴링·오프라인·저장 충돌은 작성 중인 시간 옵션도 덮어쓰지 않는다.

```json
{
  "expected_revision": 0,
  "plan": {
    "autoplay": true,
    "duration_seconds": 120,
    "items": [{"verification_job_id": "verify-example", "repeat": 1, "enabled": true}],
    "loop": true
  }
}
```

이 옵션은 **PC2 자동 재생의 목표 시간**이다. 실제 Applied 관측 이후 PC2가 상영 구간을 시작하고 당시 시간을 고정한다. 옵션 변경은 다음 상영부터 사용하며 이미 시작한 상영의 남은 시간을 바꾸지 않는다. 다음 작품 준비 실패 시 현재 작품을 유지한다. 경과·완료 증거 없이 완료 횟수를 올리거나 앱 타이머만으로 전환 성공을 표시하지 않는다.

## 실제 재생과 구분

수동 적용과 별도로 `자동 순환 재생`을 켜고 저장하면 갱신된 PC2 키트가 순서·반복·공통 시간에 따라 전환한다. 중앙 저장 revision과 PC2 보고 revision을 따로 표시한다. 앞서 승인된 [스케줄러 정책 시뮬레이션](architecture/library-scheduler.md)의 최근 30/70 자동 선택·정상 완료 횟수 집계는 이번 수동 목록 실행과 별도다. UE 프로세스를 시간마다 종료·재실행하지 않는다.

실시간 화면 스트리밍, 원격 UE 시작·중지·재시작, DMX·MIDI·색상 슬라이더는 현재 중앙 제어 계약이 없으므로 조작 가능한 가짜 버튼으로 만들지 않는다. 현재 실행 프로세스는 기존 Show Agent가 관리한다. 시연 실패·외부 생성 지연이 현재 작품을 중단시키지 않는다.

## API와 저장

| 경로 | 역할 |
|---|---|
| `GET /infra/show-dashboard?node_id=...` | 등록 시연 노드·현재 상태·검증 작품 목록·해당 노드의 중앙 구성 |
| `PUT /infra/show-dashboard/{node_id}` | expected_revision과 구성 저장. 동시 변경은409이며 새로 조회 후 검토 |
| 기존 `POST /infra/jobs/{verification_id}/approve-publication` | 운영자가 명시적으로 승인한 수동 적용 요청. 같은 요청 재시도는 동일 request_id |
| 기존 `GET /infra/jobs/{id}` | 게시 작업·실제 Applied 결과 추적 |

모두 계정 세션 또는 기존 운영자 토큰 인증을 사용한다. Agent 토큰은 대시보드 조회·설정 변경 권한이 없다. 새 `infra_show_configuration` 테이블은 노드별 revision·구성 JSON·갱신 시각을 저장하며 기존 create_all에 등록한다. 기존 테이블·UE 전달 파일·프로세스 계약은 변경하지 않는다. 카탈로그·검수 근거를 서버에서 다시 확인한다.

서버 설정을 폴링할 때 작성 중인 편집을 덮어쓰지 않는다. 저장 실패·409는 편집을 보존하고 명시적 `서버 설정 다시 불러오기`만 로컬 편집을 교체한다. 선택 노드 변경 전 편집을 정리해야 한다. 승인 요청은 사용자 확인 뒤 한 번만 전송하며 타임아웃 재시도도 동일 요청 ID를 유지한다. 인증 실패 시 자동 조회를 멈추고 현재 시연을 미확인으로 표시한다.

기본 탭을 표시한다. 필요하면 앱 실행 전 `OPERATOR_SHOW_DASHBOARD=0`으로 숨길 수 있으며 숨긴 경우 대시보드 조회를 하지 않는다. PC2 키트의 실제 설치·화면 확인은 담당자가 별도로 수행한다.
