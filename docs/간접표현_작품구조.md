# 작품 구조 (간접 표현 중심)

## 1. 우리가 만드는 예술

**간접 표현을 기본 방향으로 하되, 주인공을 직접 그리는 작품도 만든다.**

간접 표현은 대상을 직접 보여 주지 않고, 흔적과 순간의 형상으로 존재를 느끼게 하는 방식입니다.

| 직접 표현 | 간접 표현 (기본 방향) |
|---|---|
| 아름다운 사슴이 걸어간다 | **사슴의 발자취**가 남고, 번지고, 사라진다 |
| 고래가 헤엄친다 | **작은 물고기 떼**가 헤엄치다 어느 순간 **고래 모양**이 되고, 다시 흩어진다 |

간접 표현 작품에서 주인공(사슴·고래)은 화면에 그리지 않습니다. 시스템이 만드는 것은 주인공의 외형이 아니라 **주인공이 남기는 데이터**입니다.

"사람이 등장하면 풀숲에서 호랑이가 뛰쳐나온다"처럼 주인공이 화면에 직접 나와야 하는 요청도 받습니다. 이때는 주인공을 이미지로 직접 그립니다(아래 **직접** 방식).

## 2. 드러내는 방식

| 방식 | 화면 | 주인공 데이터 | 쓸 수 있는 표현 방식 |
|---|---|---|---|
| **형상** (formation) | 작은 것들이 모여 잠깐 주인공 모양이 됐다가 흩어짐 | 실루엣 점 목록 (`silhouette.json`) | 군집, 입자 |
| **흔적** (trace) | 보이지 않는 주인공이 지나간 자리에 자국이 남음 | 걸음 경로와 박자 (`path.json`) | 그리기, 유체, 표면 변형, 입자 |
| **직접** (direct) · 구현 예정 | 주인공을 이미지로 직접 그림 | 주인공 이미지 (배경과 분리된 투명 PNG, `subject.png`) | 객체 반응 |
| **없음** (none) | 주인공 없이 장(field)만 | 없음 | 전부 |

직접 방식은 아직 코드에 없습니다(`packages/contracts`의 `Reveal`에 `direct` 추가 필요). 자연어 입력을 이 값들에 매칭하는 설계는 [분산형 설계 6절 작품 명세와 추출 근거](./architecture/distributed-system-design.md#6-작품-명세와-추출-근거)에 있습니다(목표 설계, 미구현). 그 설계의 작품 명세에서는 **없음**을 `none` 대신 `field`라고 씁니다. 명세에서 `"none"`은 "운영자가 일부러 비운 칸"이라는 뜻으로 따로 쓰기 때문입니다. 이 문서와 지금 코드는 `none`을 그대로 씁니다.

테마별 기본값(비우면 이렇게 고릅니다): 바다 → 고래·형상 / 숲 → 사슴·흔적 / 우주 → 혜성·흔적 / 꽃밭 → 나비·형상

## 3. 예시: 물고기 떼로 된 고래

| 단계 | 화면 | 형상으로 끌리는 힘 | 기본 시간 |
|---|---|---|---|
| 흩어져 유영 | 물고기 수백 마리가 자유롭게 헤엄침 | 0 | 20초 |
| 모여듦 | 서서히 고래 윤곽으로 모여듦 | 0 → 1 | 8초 |
| 형상 유영 | 물고기로 된 고래가 헤엄침 | 1 | 15초 |
| 흩어짐 | 한순간 바깥으로 퍼짐 | 0 + 순간 힘 | 3초 |

- 끝나면 처음으로 돌아가 반복합니다.
- 반응 세기 칩에 따라 템포가 바뀝니다. 살며시는 1.3배 느리게, 힘차게는 0.75배 빠르게 갑니다.
- 관람객의 손(예정, 렌더러에서 구현): 모여드는 중에 손을 대면 그 부분만 흩어지고, 손을 휘두르면 흩어짐을 앞당깁니다.

## 4. 누가 무엇을 만드나

```
[우리 시스템 — 작품마다 한 번]
  input   테마 · 보이지 않는 주인공 · 드러내는 방식 · 표현 방식 · 칩 · 소재 선택
  ai      의도(주인공·드러내는 방식) → 구성 → 반응 → 안무(단계·시간·힘)
          소재: 배경(주인공 없는 분위기) + 주인공 데이터(실루엣 점 / 발자취 경로 / 주인공 이미지) → 검사 → 풀
  central 순서 · 실패 처리 · 기록 · 전달 (apps/central)
          ↓ artwork.json (+ background.png, silhouette.json / path.json / subject.png)
[렌더러 — 실시간, 매 프레임]
  UE         지금은 주인공 없는 작품(field)만. 형상·흔적은 C++ 연결 후
  TD (보관)  렌더러로 쓰지 않음. 데이터와 읽기 도구(td/artwork_reader.py)만 보관
  관람객 손 ── 카메라 → TD(센서: MediaPipe / Orbbec) → UE
```

- **영상은 렌더러가 실시간으로 만듭니다.** 미리 만든 영상 파일이 아니며, 녹화본은 홍보·발표용입니다.
- 숫자(시간·힘·색·점 위치)는 코드가 정하고, LLM은 의미(주인공, 드러내는 방식, 분위기, 반응)만 고릅니다.

## 5. 소재 만드는 법

| 소재 | 만드는 법 | 기준 |
|---|---|---|
| 배경 | AI 이미지. **주인공을 그리지 않은** 분위기(빛, 안개, 질감, 색의 층) | 어둡고 대비가 낮고 가운데가 비어 있을 것. 순수 검정(배경 없음)도 선택지 |
| 실루엣 | 주인공 윤곽 → 점 600개(윤곽 40% + 내부 60%) | 한 덩어리, 알아보기 쉬운 옆모습, 화면의 4~60% |
| 흔적 경로 | 화면을 가로지르는 곡선. 걷는 주인공은 좌우 교대 발자국(0.6초), 나머지는 이어진 자취(0.2초) | 화면 안, 6개 이상, 시간이 앞으로 감 |
| 주인공 이미지 (예정) | 직접 방식에서만. AI 이미지로 주인공만 그리고 배경은 따로 만듦 | 투명 배경, 한 덩어리, 배경과 화풍·색이 맞을 것 |
| 작은 재료 | 빛 점·붓 자국·발굽 자국 (예정) | 투명 PNG, 작은 크기 |

- **실루엣은 테마와 상관없이 풀에서 다시 씁니다.** 같은 고래를 바다·우주·꽃밭에서 다른 색으로 쓸 수 있습니다.
- 지금 실루엣은 코드로 그린 기본 윤곽(고래·물고기·새·나비)입니다. 목록에 없는 주인공은 타원으로 대신하고 기록에 표시하며, 타원은 풀에 넣지 않습니다.
- 실제 운영에서는 AI 이미지("단색 실루엣, 흰 배경") → 마스크 → 윤곽으로 바꿉니다(`packages/studio/src/studio/generation/subjects.py`의 `OutlineProvider`).

## 6. 전달 데이터 (`artwork.json`)

```json
{"SchemaVersion": 1, "title": "바다", "mood": ["calm"], "palette": ["#123a6b", "#1f8a8a"],
 "background": "background.png",
 "subject": {"name": "고래", "reveal": "formation", "file": "silhouette.json"},
 "phases": [{"name": "흩어져 유영", "seconds": 20, "target_from": 0, "target_to": 0, "burst": false}, "..."],
 "layers": [{"family": "flock", "position": "center"}],
 "reactions": [{"source": "hand", "family": "flock", "reaction": "follow", "strength": "normal"}]}
```

- 직접 방식(예정)에서는 `subject`가 `{"name": "호랑이", "reveal": "direct", "file": "subject.png"}`가 됩니다.
- `silhouette.json`: `{"points": [[u, v], ...], "outline": [...], "area": 0.16}`. 좌표는 화면 기준 0~1입니다.
- `path.json`: `{"gait": "steps", "steps": [{"t": 0.0, "u": 0.08, "v": 0.52, "side": "L"}, ...]}`
  - `t`는 '지나감' 단계가 시작된 뒤의 초입니다. 시간 길이는 그 단계 시간(템포 반영)과 같습니다.
  - 발로 걷는 주인공(사슴 등)은 `gait: steps`(좌우 발자국 L/R), 나머지(혜성·바람 등)는 `gait: trail`(이어진 자취 C)입니다.
- 전달 방식은 UE와 같습니다. `delivery_td/versions/<버전>/`에 쓰고 `release.json`을 원자 교체합니다.
- TD 안에서는 `td/artwork_reader.py`로 읽습니다(`load_current`, `phase_at`, `points`, `steps`). TD는 지금 센서 역할이라 이 경로는 보관 중입니다([td/README.md](../td/README.md)).

## 7. TD와 UE

TD는 지금 렌더러가 아니라 관람객 입력 센서입니다([TD 기능 명세](../td/docs/기능명세.md)). 아래 표는 이미지 생성 파트 상황에 따라 TD 렌더러 확장을 다시 검토할 때 쓰도록 남긴 비교입니다.

| | TD | UE (라넬 런타임) |
|---|---|---|
| 형상(물고기 → 고래) | 입자·인스턴싱 + 실루엣 점으로 끌기. 노드 작업으로 가능 | 군집에 형상 목표 기능이 없음 → C++ 추가(또는 Niagara) |
| 흔적(발자취) | 피드백·잔상 기법과 잘 맞음 | 보이지 않는 손(`trace:1`)을 UDP로 보내 표면 변형·그리기 재생 (시험 필요) |
| 직접(호랑이) | 이미지 레이어 표시·이동 (확인 필요) | 객체 반응 모듈로 이미지 표시 (확인 필요). 뛰쳐나옴 같은 등장 동작은 새로 만들어야 함 |
| 입체감 | 보통 | 강함. 애니메이션 고래 모델을 틀로 쓰면 물고기 고래가 헤엄치게 만들 수 있음(미구현) |
| 시험 속도 | 빠름 | 느림 |

설정 `RENDERER`: `both`(기본, 임시) / `ue` / `td`. `both`이면 UE가 못 하는 작품은 TD에만 보내고, `ue`이면 그런 작품은 보류합니다. TD로 보낸 데이터를 읽어 그리는 TD 네트워크는 없으며 보관 중입니다. 최종 기본값은 별도 작업에서 정합니다.

## 8. 정해야 할 것

1. UE 렌더러의 형상·흔적 구현 범위 (라넬 UE 런타임과 C++ 담당 범위). TD는 센서로 정했고, 서버의 `RENDERER` 기본값은 임시로 `both`로 두었습니다(최종 값은 별도 작업)
2. 실루엣 생성기: AI 이미지 → 마스크로 갈지, 3D 모델 표면 점으로 갈지
3. TD 렌더러 확장이 필요해지면 고래 장면 구현 담당과 일정 (지금은 보류)
4. 팀 구성도 반영: "3D 에셋 Worker"를 "주인공 데이터 Worker"로 바꾸고, TD·관람객 입력을 추가
