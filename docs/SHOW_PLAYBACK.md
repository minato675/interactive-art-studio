# PC2 재생목록과 실제 시간 전환

시연 관리의 중앙 구성은 PC2 HTTP 키트가 가져온다. 운영 앱을 닫아도 PC2가 재생을 담당한다. 기본 작품 시간은 120초이며 공통 옵션·순서·반복·사용 여부·자동 순환을 중앙 DB에 저장한다. 새 구성은 자동 순환 꺼짐·빈 목록으로 시작한다.

## 사용 방법

1. `시연 관리`의 검증 작품 목록에서 제목·작품 ID로 검색하고 이전/다음 페이지로 과거 작품을 찾는다. 검수 통과 또는 사람 승인 작품만 추가할 수 있다. 실패·반려·미리보기 예외는 자동 재생 대상이 아니다.
2. 작품을 선택하여 `재생목록에 추가`하고, 재생목록에서 위/아래·제거·반복·사용 여부를 정한다. 제거는 목록에서만 빼며 원본 작품·캐시는 삭제하지 않는다.
3. 작품당 시연 시간을 설정하고 `자동 순환 재생`을 켠 뒤 중앙에 저장한다. 저장 revision과 PC2가 동기화한 revision을 구분해서 확인한다. 꺼짐·빈 목록·마지막 작품 이후 전체 반복 꺼짐은 현재 화면을 유지한다.
4. PC2에 업데이트 키트를 적용하고 실행한다. 원격 접속이 없으므로 키트 전달만으로 현장 적용 완료로 기록하지 않는다.

## 실제 전환

파일 준비 스레드가 이미지·scene 등의 번들을 미리 내려받고 SHA-256·크기를 검증한다. 준비 중에는 `release.json`을 변경하지 않는다. 파일 준비는 Staged이며 UE Ready를 가정하지 않는다. UE watcher가 자동 commit하므로 UE 내부의 독립적인 무중단 사전 로딩을 구현했다고 표시하지 않는다.

로컬 재생 스레드가 실제 Applied·활성 버전·PID·세션을 관측하고 단조 시계로 시간을 센다. 기본 120초가 지나면 다음 작품이 로컬에서 준비된 경우에만 기존 단일 UE에 포인터 교체를 요청한다. 새 작품 Applied를 확인해야 새 구간 시간을 시작한다. 다음 작품 미준비·파일 손상·중앙/다운로드 실패는 현재 포인터를 유지하고 기다린다. 적용 실패는 기존 자동 복구 관리자의 마지막 정상 작품 복귀를 사용한다. 준비 실패와 실제 UE 적용 실패는 구분한다.

120초는 전환 목표다. 다음 작품이 미준비이면 현재 상영은 연장된다. 로컬 관측 주기와 UE 적용 지연이 있으므로 프레임 단위의 정확한 120초 전환·무중단 출력이 검증됐다고 표시하지 않는다.

공통 시간 변경은 다음 상영 구간부터 적용한다. 진행 중인 구간의 시간을 다시 세거나 짧게 자르지 않는다. 동일 작품 반복은 이미 Applied인 작품을 유지하면서 다음 시간 구간을 시작한다. Agent 재시작·Runtime 세션 변경은 남은 시간을 추정하지 않고 새 구간으로 시작한다. 관측이 끊기면 상영 완료 횟수를 생성하지 않는다.

중앙 동기화·다운로드와 시간 관측은 별도 스레드다. 마지막 구성 JSON과 검증한 불변 작품 폴더로 통신 단절 중에도 재생한다. 미캐시된 다음 작품이 있으면 현재 작품을 유지한다. 수동 게시와 자동 전환은 같은 로컬 잠금으로 직렬화한다. UE를 하나 더 실행하지 않으며 명시적으로 정지한 관리 모드에서는 전환하지 않는다.

## 통신 계약

| 경로 | 권한·내용 |
|---|---|
| `GET /infra/show-dashboard?library_offset=0&search=...` | 운영자: 과거 검증 작품을 페이지로 조회·검색, 현재 중앙 구성과 Agent 재생 보고 |
| `PUT /infra/show-dashboard/{node_id}` | 운영자: revision CAS, `plan.autoplay`, 공통 `duration_seconds`, items·loop 저장 |
| `GET /infra/agent/show-playlist` | 등록된 show/ue_publish 노드: 자기 구성·호환/승인 작품의 불변 파일 명세만 조회 |
| `GET /infra/agent/show-playlist/{verification_id}/files/{sha256}` | 해당 노드 재생목록에 포함되고 현재 승인·카탈로그를 만족하는 파일만 인증 다운로드 |
| `POST /infra/agent/heartbeat` | 기존 ShowReport에 `playback` 추가: 적용 구성 revision, 상태·현재/다음 검수 ID·구간 시간·캐시 수·마지막 동기화·오류. Applied/프로세스 근거는 기존 필드 유지 |

노드 토큰을 UI·JSON 상태 파일·로그에 기록하지 않는다. 중앙 상태는 마지막 수신 시각을 함께 표시하며 오래된 보고를 현재 재생 성공으로 취급하지 않는다. 파일 다운로드 권한은 임의 해시 조회나 다른 노드의 목록으로 확장하지 않는다.

## 설치 범위와 검증

키트에는 `show_playback.py`와 갱신된 `runtime_worker.py`를 함께 전달한다. 서버·PySide6도 같은 계약으로 갱신해야 한다. 기존 `node.secret.json`, `server.json`, `runtime.local.json`, Shipping 실행본·delivery·bootstrap·정상 작품 기록은 유지한다. 업데이트 중 Agent만 재시작하며 별도 지시 없이 UE를 종료하거나 토큰을 재발급하지 않는다.

가상 시계 검사와 실제 시험 자식 프로세스 검사를 UE/GPU·LED 현장 검증과 구분한다. 원격 접속이 없는 PC2의 설치·실제 화면·센서 검증은 담당자 확인이 필요하다. 구체적인 수행 결과는 작업 완료 시 아래에 기록한다.
