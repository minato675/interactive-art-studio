# 제작노드 이미지 스킬 사용 안내

이 문서는 생성 PC·UE 제작 PC의 제작 지침과 중앙 Head의 감독 스킬을 Git으로 전달하고 사용하는 방법을 설명합니다.
최초 전달은 `S15P31A504-199`, 감독 지침과 배포 패키지의 영속화는 `S15P31A504-208`에서 다룹니다.

## 1. 어떤 PC에서 무엇을 사용하는가

| 장비 | 스킬의 용도 | 별도로 필요한 것 |
|---|---|---|
| 생성 PC | 배경·에셋의 표현 기획, 실제 이미지 생성·편집 | 사용 가능한 이미지 생성 도구, 결과 저장 폴더 |
| UE 제작 PC 1·2 → N대 | 결과의 깊이·재질·운동 의도 파악, UE 구성·검토 지침 | UE·플러그인·입력 에셋·조립 프로그램 |
| 중앙 Head | 템플릿·배경·원본 에셋·복제 배치·반응·효과·입자와 검수의 감독 | 배포 패키지에 포함된 지침 로더, 사용 가능한 판단 모델·제작 노드 |

저장소의 현재 장비 구분에서 배경·에셋 생성은 생성 PC, UE 조립은 제작 PC의 일입니다.
Git 수신은 이미지 도구·UE·모델 설치를 대신하지 않습니다. 중앙 Head에는 별도 로더를 연결했으며,
새 Head 요청의 배경·에셋·검수 판단에 패키지의 감독 지침을 포함합니다. 파일 수신만으로 제작을 시작하지 않습니다.
전체 계약과 현재 실행 범위는 [시나리오 감독](../infra/HEAD_SCENARIO_DIRECTOR.md)을 따릅니다.

## 2. Git으로 받기

저장소를 이미 받은 PC에서는 작업 파일을 보존한 상태에서 아래 브랜치를 받습니다.
다음 예시는 작업 파일이 없고 로컬 `develop`이 있는 PC 기준입니다. 다른 작업 중이면 별도 worktree로 받습니다.

```powershell
git fetch origin
git switch develop
git pull --ff-only origin develop
git rev-parse HEAD
Get-ChildItem .agents/skills -Directory
```

검증 후 `develop`에 병합된 버전을 사용합니다. `.agents/skills`의 세 폴더와 하위 파일을
함께 유지하며, 개인 사용자 스킬 폴더에 다시 복사할 필요는 없습니다.

원본 대비 변경과 배포 파일 해시는 `.agents/skills/distribution.json`에 있습니다.
텍스트 해시는 LF 줄바꿈 기준이므로 Windows/Linux 체크아웃 사이에서도 비교할 수 있습니다.
PNG는 원본 바이트 기준입니다. 세 폴더의 복사 대상 파일은 현재 43개입니다.
라넬 스킬은 Head 패키지의 사본과 동기화하고, 실제 런타임 프롬프트는 `.gitattributes`로 LF를 고정합니다.

## 3. Codex에서 선택하기

Codex를 저장소 루트에서 시작합니다. 프로젝트 스킬 경로는 `.agents/skills`이며,
폴더 구조와 탐색 규칙은 [공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)를 참고합니다.

```powershell
codex
```

대화에서 `/skills`로 세 스킬이 보이는지 확인합니다. 보이지 않으면 작업 디렉터리가 이 저장소인지,
`SKILL.md`가 존재하는지 확인한 뒤 Codex를 다시 시작합니다. 같은 이름의 개인 스킬이 이미 있으면
프로젝트 경로의 스킬을 명시해 버전을 구분합니다. 기존 개인 스킬을 자동 삭제하거나 덮어쓰지 않습니다.

| 스킬 | 선택 기준 |
|---|---|
| `$ranel-ue-media-art` | EARTH 자연 현상과 시나리오 감독, 실제 배경 분석, 에셋 복제·배치·관객 반응·검수 |
| `$ue-led-media-art` | 네 화가의 조형 원리 융합, 기존 LED 작품 방향을 명시적으로 원하는 작업 |
| `$imagegen` | 실제 이미지 생성·편집 도구를 사용하는 작업 |

주된 제작 방향으로 앞의 두 스킬 중 하나를 고릅니다. 둘은 영상 길이·출력 전제 등이 다르며,
현재 EARTH 목표는 12m×3m 직선 벽과 4:1 구도입니다. 예전 6m×6m·120초 조건을 일괄 적용하지 않습니다.
Head의 현재 배경 권장 1920×1080 및 실행 매핑과 목표 화면 비율의 차이는 별도 검수 대상입니다.
이미지 실행이 필요하면 `$imagegen`을 함께 지정합니다. 설치된 도구와 계정의 사용 가능 여부는
해당 PC에서 확인합니다.

## 4. 생성 PC 요청 예시

아래 문장은 Codex 대화 입력 예시입니다. PowerShell에 명령어로 붙여 넣지 않습니다.
출력 폴더와 요구 해상도는 실제 작품 요청에 맞춥니다.

### 배경 만들기

```text
$ranel-ue-media-art $imagegen
깊은 바닷속을 주제로 21:9 배경 이미지 1개를 만들어줘.
앞·중간·뒤의 깊이와 빛의 방향을 분명히 하고, 이후 에셋을 배치할 여백을 남겨줘.
완성 파일은 runtime/artworks/demo-v1/background/에 저장하고 실제 크기와 생성 도구를 기록해줘.
```

### 실제 배경을 보고 에셋 N개 만들기

```text
$ranel-ue-media-art $imagegen
runtime/artworks/demo-v1/background/의 실제 배경 이미지를 먼저 열어 확인해줘.
그 배경과 조명·원근·재질이 어울리는 에셋 3개를 각각 독립된 투명 배경 PNG로 만들어줘.
각 에셋의 2D/2.5D 표현 의도를 설명하고 runtime/artworks/demo-v1/assets/에 저장해줘.
깊이맵·마스크·레이어는 실제 생성한 파일만 결과 목록에 적어줘.
```

개수 3은 예시입니다. 실제 요청의 N을 사용하며, 제작 실행기 2개가 있다고 에셋이 2개로 제한되는 것은 아닙니다.
배경·원본·이전 버전을 보존하고, 실제 알파·경계·배경과의 조화를 확인합니다.
2.5D 지침의 존재만으로 깊이맵 생성이나 UE 임포트가 자동 구현된 것으로 기록하지 않습니다.

## 5. 도구·API 사용 범위

동봉된 `imagegen`의 기본 경로는 사용 가능한 내장 이미지 도구입니다. 해당 PC에서 도구가 없으면
생성 완료로 처리하지 말고 사용 불가를 기록합니다. 스킬이나 토큰만으로 도구가 새로 생기지는 않습니다.
Codex 대화의 이미지 제작은 요청한 도구 정책을 따릅니다. EC2 Head는 이미지 자체를 생성하지 않고
등록된 생성 노드에 제작 지시를 전달합니다. Head의 GMS 판단 모델과 실제 이미지 생성 도구는 별개입니다.
스킬 전달·패키지 검증에는 유료 이미지 호출이 필요하지 않습니다.

실행 경로의 무과금 점검은 저장소 루트에서 할 수 있습니다. Python 3.12 이상과 uv가 준비된 PC 기준입니다.

```powershell
uv sync --locked
$imageGen = Join-Path (Get-Location) '.agents/skills/imagegen/scripts/image_gen.py'
uv run python $imageGen --help
uv run python $imageGen generate --prompt 'A calm blue underwater background' --out runtime/skill-check/background.png --dry-run
```

`--dry-run`은 요청 내용을 출력하며 이미지를 만들지 않습니다. 키나 `openai` 패키지가 없어도 실행할 수 있습니다.
원본 스크립트에는 일괄 생성·편집·크로마키 도구도 포함되어 있습니다. 실제 API 생성에는 별도 `openai`,
실제 크로마키·일부 이미지 처리에는 `Pillow`가 필요할 수 있으며 이번 변경에서는 설치·의존성 추가를 하지 않습니다.
도입 시 저장소의 uv·라이선스 규칙에 따라 구성합니다. 키는 장비의 비밀 설정으로만 관리합니다.

현재 동봉된 API CLI는 직접 OpenAI 클라이언트 경로입니다. GMS 토큰으로 동작한다고 가정하거나,
Head의 판단 모델이 곧 이미지 생성 모델이라고 해석하지 않습니다. GMS 이미지 생성 지원·주소·인증은 별도 검증 대상입니다.

## 6. 결과와 중앙서비스 연결

작업 단위로 작품 ID·버전, 배경/에셋 구분, 실제 파일명·크기·SHA-256, 입력 배경 참조,
사용 도구·모델(확인한 경우), 알파·깊이 데이터 유무, 검증 상태를 기록합니다.
기록 양식은 `ranel-ue-media-art/assets/artwork-record.json`을 작업 폴더로 복사해 사용할 수 있습니다.

생성 중에는 무시되는 `runtime/`에 저장하고, 현장 결과 전송은 [공유 저장소 규칙](../infra/STORAGE.md)을 따릅니다.
완성된 결과를 생성 PC의 전용 자산 저장소에 반영한 뒤 기존 생성 결과 보고 경로와 연결해야 합니다.
Head는 신규 요청에 지침 버전·해시를 고정하고 실제 반환 배경을 본 뒤 감독 명세를 저장합니다.
원본 생성과 복제 배치를 구분하고 현재 조립 계약에 연결한 값만 실행합니다. 기존 업로드·작업 임대 경로를 사용합니다.
Git에 생성 이미지나 토큰을 함께 올리지 않습니다.

UE 제작 PC에서는 실제 전달받은 파일을 열고 다음처럼 요청할 수 있습니다.

```text
$ranel-ue-media-art
전달받은 배경과 에셋 파일, 실제 UE 버전과 프로젝트 지침을 확인해줘.
원근·가림·재질·알파·깊이 레이어를 UE에서 어떻게 구성할지 정리하고,
실제 실행한 검사와 아직 미구현인 조립·쿠킹·렌더를 구분해서 보고해줘.
```

생성 성공, 기술 검사, UE 화면 확인, 시연 Ready/Applied, 게시 승인은 각각 별개입니다.

## 7. 참고 이미지와 이번 점검 범위

회사 참고 이미지의 개인 절대 경로는 배포본에서 `runtime/references/company`로 바꿨습니다.
이 경로는 저장소 루트 기준입니다. 참고 이미지 원본은 Git에 포함하지 않으므로 제공받은 자료를
각 PC에서 별도 배치하고 존재 여부·이용 조건을 확인합니다. 원본이 없으면 해당 레퍼런스를 직접 봤다고 쓰지 않습니다.
`references/project-context.md`와 출처 기록은 작성 당시의 자료 상태이며 현재 장비 설정을 대신하지 않습니다.

복사 시 점검한 항목은 스킬 구조, 로컬 링크, 개인 사용자 경로·키 형식, JSON,
두 Python 스크립트 구문·help, 이미지 CLI dry-run입니다. `imagegen` Apache-2.0 라이선스와
두 실행 스크립트의 내용은 보존했습니다. 외부 원문 두 스크립트의 Ruff 제외 근거는
[외부 도구 고지](THIRD_PARTY.md)에 있습니다.

실제 제작노드의 Codex 스킬 인식, 내장 도구 사용, 유료 이미지 생성, GMS 연결, UE 렌더는
이번 파일 전달만으로 검증한 항목이 아닙니다.

Head 운영 이미지의 스킬 포함 여부는 기존 `infra/check_packaged_scene.py`에서 설치된 wheel의 파일 목록·해시와
세 판단 단계의 지침 로딩으로 검사합니다. CI `build-smoke`와 정상 배포가 이 검사를 실행하므로 패키지에서
감독 스킬이 빠진 이미지는 통과하지 못합니다. 시나리오의 관객 반응·현장 영상 품질은 별도의 실행 증거가 필요합니다.

### 2026-10-21 로컬 검증 결과

- 세 스킬의 구조 검사와 배포 대상 36개 파일의 해시·JSON·상대 링크 검사 통과.
- 개인 사용자 절대 경로·키 형식 검사와 기존 로컬 자격 증명 일치 검사 통과. 실제 키는 읽은 값이나 로그로 공개하지 않음.
- 두 스크립트의 구문·`--help`, 이미지 생성 CLI `--dry-run` 통과. 유료 API 호출 없음.
- `uv run pytest -q`: 241개 통과, 실제 PostgreSQL 환경이 필요한 5개 건너뜀.
- `uv run ruff check .`: 통과. 외부 원문 두 스크립트는 위 고지에 따라 제외.
- 기존 Starlette TestClient 사용 중단 예정 경고 1개가 있으며 테스트 실패는 없음.

이 결과는 스킬 전달 브랜치의 `develop` 기준 결과입니다. 별도 Head 브랜치의 테스트 개수와 합산하지 않습니다.
