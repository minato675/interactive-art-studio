# 제작 정책: 모드·지원 검사·두 출력 준비·실제 적용

2026-10-21 사용자 결정에 따른 구현 기준입니다. 이전 파일별 비교에서 보류했던 세 정책을 대체합니다.

## 기획

- `mode=exhibition`: 테마에서 주인공과 표현을 자율 선택할 수 있습니다. 현재 UE 어댑터는 형상·흔적이 미지원이므로 UE를 포함한 자동 기획은 별도 요구가 없을 때 장 표현으로 시작합니다. TD만 선택하면 테마별 주인공 기본값을 사용할 수 있습니다. 사용자가 명시한 주인공·표현을 빼서 성공시키지는 않습니다. LLM이 설정된 서버에서 테마가 비어 있으면 AI 미디어아트 디렉터가 렌더러별 지원 범위(`capabilities`) 안에서 방향을 제안하고, 코드 검사와 계획 검사를 소재 생성 전에 통과해야 합니다. 틀리면 이유를 붙여 다시 쓰게 하며 디렉터를 최대 3번 부르고(처음 1번 + 다시 쓰기 2번), 연결 실패나 소진이면 위 프리셋 규칙으로 대체합니다(실패 아님). 설계는 [전시 모드 디렉터 설계](../superpowers/specs/2026-10-22-exhibition-director-design.md)입니다.
- `mode=manual`: 프롬프트·명시 입력에 근거해 기획합니다. 바다라는 이유로 고래를 고정 추가하지 않습니다. 프롬프트에 주인공을 적었다면 별도 subject 입력 없이도 추출합니다. 원문에 주인공이 있는지는 Input Agent(`studio/head/spec_matching.py`)가 판단합니다. 메인 캐릭터가 없으면 '드러내기 없음'으로 기획하고, 있으면 기획이 그 메인 캐릭터 문구 안에서 주인공을 고르며 선택 렌더러가 표현하지 못하면 오류입니다. 관람객('사람이 등장하면')이나 장면 요소를 주인공으로 만들어 실패하지 않기 위해서입니다.
- 운영 앱의 한 번에 제작/초안 편집은 위 모드와 별개입니다. 초안 확정은 이미 확인한 계획을 다시 생성하지 않습니다.

## 지원하지 않는 요청

미지원 칩·참고 이미지·입력·시간 구조·표현 방식과 선택 렌더러가 구현하지 못한 요구는 오류입니다. 요청을 누락하거나 다른 렌더러만 성공시켜 정상 완료하지 않습니다. 요청에서 확인 가능한 항목은 생성 전에 검사하고, 기획 결과와 초안 확정 결과도 검사합니다. 오류 항목과 원인을 기록하고 현재 작품을 유지합니다. 사람의 검수 반려(`held`)와 지원 오류(`failed`)를 구분합니다.

## both와 파일 준비

`both`의 필수 출력은 TD `artwork.json`과 UE `scene.json`입니다. 두 출력의 조립·검사·파일 준비가 모두 성공해야 `prepared`가 됩니다. 한쪽 실패는 전체 작업 실패이며 출력별 원인을 기록합니다. 최종 검수 후보와 승인 후 전달에도 같은 규칙을 적용합니다. 예전 검수 기록에서 필수 출력이 누락됐다면 승인으로 우회하지 않습니다.

후보 파일은 버전 폴더에 준비하지만 `release.json`을 변경하지 않습니다. 두 개의 독립 포인터를 순차 교체하고 실패 후 되돌리는 방식은 중간 노출을 막을 수 없기 때문입니다. 준비된 후보의 활성화는 별도 시연 경로에서 요청합니다. 기존 UE·TD 원본 watcher는 변경하지 않습니다.

## 상태 구분

| 상태 | 의미 |
|---|---|
| `prepared` | 모든 필수 후보 파일 준비 완료. 런타임 Ready·Applied는 미확인 |
| `failed` | 지원 검사·생성·검사·파일 준비 중 실패. 현재 활성 포인터 유지 |
| `Staged` | Show Agent 로컬 캐시에 파일 준비 완료 |
| `Ready` | 실행 중인 UE가 요청 버전을 준비했다고 보고. 현재 활성 버전과 구분 |
| `Applied` | 실행 중인 UE가 요청 버전을 실제 활성화했다고 보고 |

Show Agent는 실제 프로세스·세션·요청 버전과 런타임 보고를 검증합니다. 파일 복사나 후보 준비 결과에서 Ready·Applied를 만들어내지 않습니다. 현재 동기 제작 API와 분산 Show Agent는 별도 경로이며, 제작 API 응답에 실제 시연 보고가 연결되지 않았을 때는 미확인으로 표시합니다. 기존 UE watcher의 준비 후 자동 commit은 유지되며 중앙에서 Ready 후 별도 commit을 보내는 프로토콜을 구현했다고 주장하지 않습니다.

## 검증 기준

규칙 기반 원문 추출은 명칭 목록과 `주인공: 이름` 구문에 한정됩니다. 자유로운 이름은 LLM의 원문 근거 또는 명시 subject 입력이 필요합니다. 자연어의 모든 미지원 요구를 이해하는 완전한 의미 검증기는 아니며, 현재 구조화된 요청 항목과 생성된 계획의 지원 여부를 검사합니다.

모드별 주인공 선택, 사용자 요구 보존, 미지원 요청의 생성 전 오류, TD/UE 각각의 준비 실패, 두 기존 활성 포인터 유지, 검수 재개, Ready/Applied/과거 상태 구분을 회귀 검사합니다. 실제 UE·TD 화면·성능·무중단 전환은 별도 장비 검증 사항입니다.
