## 후속 결정과 남은 논의

### A. 테마만으로 주인공·표현 방식을 고르는 정책

직전본은 바다→고래·형상 등을 선택하고 !23은 기본 주인공 없음으로 바꿉니다. 기존 테스트는 전자를 기대하지만, 테스트가 존재한다는 사실만으로 최종 사업 요구가 확정됐다고 볼 수 없습니다. !10의 직접 표현 추가와 명세 체계 확장도 있어 어느 한쪽을 전체 작품 규칙으로 단정하면 안 됩니다.

**사용자 결정 — 확정·구현:** 두 동작을 모드별로 유지합니다. 전시 모드는 주어진 테마와 지원 범위 안에서 주인공·표현을 자율 기획합니다. 사용자 프롬프트 제작은 입력 내용에 근거해 기획하며, ‘바다’라는 이유만으로 고래를 고정 추가하지 않습니다. 사용자가 프롬프트에 고래를 요청했다면 별도 subject 칸이 비어 있어도 그 요구를 반영해야 합니다. 명시적 사용자 요구는 전시 모드에서도 존중합니다. 고래 자동 선택을 모든 모드에 적용하거나 모든 모드에서 제거하는 방식은 사용하지 않습니다.

현재 계약에는 `Mode.exhibition/manual`이 이미 있습니다. 운영 앱의 ‘한 번에 제작/초안 편집’ 선택과 전시/사용자 제작 모드를 혼동하지 않아야 합니다. 정확한 프롬프트 추출·기획 연결은 후속 구현 사항입니다.

### B. 미지원 칩·참고 이미지·몸/소리 입력

직전본에는 일부 칩을 실제 결과에 연결하지 못하거나 미연결 입력에 알림을 남기고 진행하는 동작이 있습니다. !23은 이를 생성 전 보류하도록 바꿨습니다. 요구를 조용히 무시하지 않는 개선 목적은 합당하지만, 기존 운영 화면의 모든 선택지를 일괄 차단할 정책 합의나 대체 구현은 확인되지 않았습니다.

**사용자 결정 — 확정·구현:** 지원하지 않는 요청은 오류 처리합니다. 요청을 누락하거나 경고만 남겨 정상 완료로 처리하지 않습니다. 오류 원인과 지원하지 않는 항목을 표시하고 현재 전시 작품은 유지합니다. 생성 전에 알 수 있는 지원 여부는 먼저 검사하고, 기획 결과에서 발견된 미지원 기능도 성공으로 넘기지 않습니다. 동일한 미지원 요청을 그대로 재시도하여 성공하는 것으로 간주하지 않습니다. 작품 처리 중 미지원은 `failed`와 오류 원인으로 기록하며, 입력 형식 자체가 잘못됐을 때는 HTTP 422로 응답합니다.

이는 미지원 요청에 대한 정책입니다. 지원하는 기능의 파일 전달이 디스크·통신 장애로 실패한 경우는 C의 부분 성공 및 재시도 정책과 구분합니다.

### C. `both`에서 일부 렌더러만 성공한 결과

직전본은 TD만 성공해도 `published`와 UE 제외/실패 알림을 남깁니다. !23은 TD 경로 자체를 제거했습니다. 사용자가 `both` 복원을 확인했으므로 두 출력 경로는 필요하지만, 부분 성공을 전체 작품 성공으로 볼지는 별도 문제입니다.

**사용자 결정 — 확정·구현:** `both`는 TD·UE 모두 필수입니다. 조립·검사·파일 준비 중 하나라도 실패하면 `failed`이며 두 활성 포인터를 유지합니다. 전체 후보 파일이 준비되어야 `prepared`가 됩니다. 파일 준비와 실제 런타임 Ready·Applied는 구분합니다. 구체적인 구현과 검증은 [제작 정책](creation-policy.md)을 따릅니다.


### D. UE 숫자·성능·연출의 실제 호환성

!23의 팔레트와 위치 전달은 JSON·compiler 결과로 확인할 수 있어 유지 근거가 있습니다. 다만 `mood`는 메타데이터 보존이며 감정별 UE 효과 구현을 뜻하지 않습니다. 실제 UE 버전·플러그인·카탈로그에 대한 실기 판단은 이번 비교만으로 할 수 없습니다. controller의 기존 3개 차이 파일도 이 검토에서 변경하지 않습니다.

## 후속 작업 보존 여부

명세 스키마·명세 매칭·GMS/EXAONE 연결·최신 응답 검사, 전체 명세 편집 결정 문서, PostgreSQL·RabbitMQ 작업 API, Node/Show Agent, CI 설정을 `8928524`와 비교했습니다. 관련 구현 파일에는 !23으로 인한 내용 차이가 없고 이번 후보에서도 그대로 유지합니다. 전부 과거 커밋으로 되돌아갔다고 표현하는 것은 정확하지 않습니다.

주된 회귀는 설정·호출 차단·TD 경로 제거와 문서 범위 변경입니다. 격리 파일의 추가 판단은 이 문서 범위 밖이며, 그 의존성 복원 기록은 [후속 개발 복원 기록](post-mr23-restoration.md)에 분리했습니다.

검증 결과와 로컬 적용 범위는 위 복원 기록을 따릅니다. 파일별 비교 원문은 별도 출력 폴더의 `before/`·`after/`·`diffs/`에 저장합니다.
