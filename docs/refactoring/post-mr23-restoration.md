# MR !23 이후 개발 기능 복원

**후속 확정 및 구현:** 1·2·3번 정책 모두 사용자가 확정했습니다. 현재 동작과 검증 결과는 [제작 정책](creation-policy.md)을 우선합니다. 아래 비교·복원 기록은 정책 적용 이전 이력입니다.

격리 파일을 제외한 수정 파일 37개의 개별 채택 근거와 판단 보류 항목은 [파일별 비교 판단서](mr23-file-decisions.md)에 있습니다. 정책 판단이 보류된 부분은 직전 개발 호환 동작을 유지한 로컬 후보이며, 최종 제품 정책 확정을 뜻하지 않습니다.

후속 사용자 답변으로 세 정책 모두 확정·구현했습니다. 아래 복원 과정과 204개 테스트 결과는 정책 적용 전 이력입니다. 최종 모드 분리·미지원 오류·both 전체 준비 및 실제 적용 구분은 [제작 정책](creation-policy.md)을 따릅니다.

## 기준과 원인

수정 시작점은 `origin/develop`의 `ae339ce937807bbd554da1bb0cd051e39663c1f1`입니다. MR !23(`cc4a2fb`)의 부모인 `8928524ca9cdb094ea91235625c61732bcd55285`를 후속 개발의 복원 기준으로 사용합니다. !2·!3 시점의 파일이나 archive 사본으로 덮어쓰지 않습니다.

MR !23도 Git 기준으로는 최신 develop 위에서 작성됐습니다. 문제는 과거 구현을 격리하는 과정에서 **이후 담당자가 유지하기로 한 개발 설정과 그 기능에 의존하는 경로까지 제거했다는 점**입니다. 특히 !12에서 정한 `both`, !13의 편집·확정, !20의 사람 검수를 목표 아키텍처만으로 차단했습니다. 테스트도 새 차단 정책에 맞춰 변경하여 기존 기능을 사용할 수 없는 회귀를 발견하지 못했습니다.

사용자는 TD 담당자가 정한 `both`를 복원하도록 명시했습니다. 최종 전시 구조와 현재 개발 경로를 구분하고, 현재 경로를 없애려면 대체 구현과 담당자 합의가 먼저 있어야 합니다.

## 최초 복원 범위 (후속 정책 적용 전)

- `central`의 설정·앱 초기화·제작·확정·검수와 TD/UE별 전달 경로를 최신 정상 기준에서 복원합니다. `ENABLE_LOCAL_PREVIEW`로 전체 API를 차단하던 정책을 제거합니다. 운영자 인증은 그대로 둡니다.
- `td_artwork.py`, `subjects.py`, `choreography.py`, `td/artwork_reader.py`, `td/formation_sim.py`를 원래 경로로 복원합니다. `both` 구현의 의존성과 기존 개발 테스트에 필요합니다. archive에서 import하지 않습니다.
- 기획의 기존 subject/reveal 선택과 렌더러별 보류 처리를 복원합니다. UE만 선택했을 때 UE 미지원 형상·흔적은 보류하며, `both`에서는 기존 TD 파일 생성 경로로 이어집니다. TD 파일 생성만으로 실제 TD 네트워크에서 재생됐다고 판단하지 않습니다.
- MR !23의 출처 조사·3개 차이 원문·14개 보관 사본·manifest는 보존합니다. 보관 폴더는 계속 테스트 수집과 배포 이미지에서 제외합니다.
- 사용자 색·분위기·위치 전달 개선, 모의 손 입력 source 정합성, 파일 게시와 실제 Applied를 구분하는 안내는 복원 기능과 양립하는 범위에서 유지합니다.

## 개발 배치와 전시 목표

일반 개발 실행과 `infra/docker/compose.yaml`은 `both`를 기본으로 사용합니다. PostgreSQL·RabbitMQ·Agent를 함께 쓰는 `infra/compose.yaml`은 이전부터 `ue`였으므로 그대로 둡니다. 두 Compose의 목적이 다르며 한쪽 값을 다른 쪽에 일괄 적용하지 않습니다.

제작 노드 N대와 독립 시연 노드 1대라는 목표는 유지합니다. 동기 프로토타입은 실제 UE 조립·시연 적용까지 연결된 분산 파이프라인을 대신하지 않습니다. `published`는 후보 파일 전달, `Applied`는 시연 런타임의 실제 활성 상태입니다.

## 검증

복원 후 전체 pytest, Ruff, controller 테스트와 기본 `both`의 제작·초안 확정·검수·두 렌더러 파일 출력을 확인합니다. Docker 테스트 이미지에는 복원한 TD 파일과 기존 센서 fixture가 함께 들어가야 합니다. 실제 UE·TD 장비 재생, 유료 외부 API, 무중단 전환은 이 소프트웨어 검증에 포함하지 않습니다.
