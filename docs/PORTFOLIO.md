# 포트폴리오 설명

## 개요와 참여 범위

기획·생성·검증·조립·전시 운영을 단계로 나누는 인터랙티브 미디어아트 팀 프로젝트입니다.
김지호 명의의 GitLab 작업 기록에서 운영 대시보드·작품 선택 재생·분산 Head 접수·대기 복구·오류 진단 참여를 확인했습니다.
회사 UE·TD·controller 원본과 팀 개발 코드를 분리해 이 저장소에는 선별한 소스만 게시했습니다.

## 대표 사례: 제작 준비와 실제 적용 상태 분리

- 상황: 후보 파일이 준비된 상태와 시연 장치가 실제로 적용한 상태는 서로 다릅니다.
- 과제: 운영 화면과 작업 기록에서 준비 완료를 실제 전시 성공으로 오해하지 않게 해야 했습니다.
- 행동: 중앙 API·시연 Agent·운영 화면에서 진행 상태와 실제 보고를 구분하고, 제작 접수·대기·복구와 오류 진단을 연결한 작업 기록이 있습니다.
- 결과: 관련 코드와 원본 커밋을 근거로 소프트웨어 경계를 설명할 수 있습니다. 실제 UE/TD 출력·GPU 성능·현장 무중단 전환의 완료 여부를 이번 발췌본으로 입증하지 않습니다.

## 기술 선택과 자료 기반 회고

원본은 FastAPI·Pydantic·SQLModel·PySide6와 분산 Agent 구성을 사용합니다.
기술 선택 이유와 목표 배치는 원본 `docs/architecture`에 있으며, 목표 설계를 현재 구현 완료로 바꾸어 설명하지 않습니다.
Keep은 준비·실제 적용·실패 상태를 구분한 접근, Problem은 회사 런타임 의존성과 팀 확장을 분리해 전달해야 하는 점입니다.
향후 제안은 승인된 외부 의존성의 계약 버전과 실제 시연 검증 결과를 별도 증거로 연결하는 것입니다.
시각화는 운영 앱·중앙 API·제작 Agent·시연 Agent의 상태 보고 흐름도를 우선합니다.
