# 작품 제작 제출과 PC1 공동 전환 안내

2026-10-25 기준. 운영 앱의 **자동 모드 제출**은 EC2 작업함에 원문을 저장합니다.
편집 모드와 기존 작품 기록은 기존 동기 API를 유지합니다.

## 운영자가 보는 흐름

1. 제출 → `POST /infra/head/intakes` → 접수 번호 반환(HTTP 202).
2. UE 설치 지문이 맞지 않으면 `waiting_ue`. 원문은 DB에 남고 생성 API를 호출하지 않습니다.
3. 설치 조건이 맞으면 Dispatcher가 다시 등록하고 Worker가 GMS로 명세를 해석합니다.
4. 중앙 Head가 배경 생성 → 배경 관찰 → 에셋 N개 생성 → UE 조립 → PC1 실행 검증을 연결합니다.
5. 기술 판정과 Head 검수·게시 승인 조건을 통과하면 PC2에 게시합니다. 실제 `Applied` 보고 후 완료로 표시합니다.

접수 작업 성공(`succeeded`)은 Head 흐름 생성 성공입니다. 작품 제작이나 PC2 적용 완료를 뜻하지 않습니다.
응답을 잃어 다시 제출할 때는 같은 요청 ID를 사용해 중복을 방지합니다. 앱을 다시 실행한 경우에는 먼저 기록에서 접수 여부를 확인합니다.
최종 검수를 선택하면 PC1 검증 후 게시 승인을 기다립니다. 기술 판정 `review`는 사람 검수로 보냅니다.
소재 중간 검수·복수 표현 방식은 자동 모드에서 아직 지원하지 않아 제출 시 안내합니다.

## UE 담당자와 함께 할 전환

이는 담당자 제공 정보이며 이번 접수 기능 배포에서 해당 소스·실행본 설치나 호환 검증까지 완료한 것은 아닙니다.

1. UE 담당자와 중앙 담당자가 배포할 전체 소스 SHA, 실행본 빌드, 실행본의 지원 카탈로그를 확정합니다.
2. PC1 조립·검증 실행기를 멈추고 진행 중 작업을 마무리합니다. PC2는 현재 작품을 유지합니다.
3. PC1에 확정 소스와 실행본을 설치합니다. 실행기에 쓰는 **동일한 Python**으로 모듈 경로와 실제 Git revision을 확인합니다.
4. 그 환경에서 `infra/ue_capabilities.py --export-catalog <출력파일> --source-revision <전체SHA> --source-merge-request 57`로 카탈로그를 내보냅니다. 이 명령은 파일만 저장합니다.
5. 중앙 담당자가 파일별 해시·대응표·슬롯·실행본 지원을 검토하고 중앙 카탈로그를 같은 기준으로 배포합니다. 기존 진행 작업에 고정된 지문은 덮어쓰지 않습니다.
6. PC1에서 같은 Python과 기존 키트의 `ue_worker.py --report-capabilities`로 설치 보고 후 조립·검증 실행기를 재개합니다. 토큰을 새로 발급할 필요는 없습니다.
7. 중앙의 `GET /infra/head/templates`와 사전 확인에서 일치·온라인 상태를 확인합니다. 조건이 맞으면 대기 중 #75가 자동 재개되므로 중복으로 새 요청을 만들지 않습니다.
8. #75의 실제 생성 파일, UE 조립 결과, PC1 보고서·캡처·verdict, PC2 Applied를 차례로 확인합니다. `review`는 사람 검수로 보냅니다.
