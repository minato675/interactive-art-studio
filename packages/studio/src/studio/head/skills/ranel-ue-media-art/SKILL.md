# 라넬 EARTH 시나리오 감독과 미디어아트

기본 방향은 **관객의 존재와 움직임이 자연 현상의 씨앗이 되어 화면 전체로 번지고, 서로 합류하며, 떠난 뒤에도 흔적이 남았다가 천천히 사라지는 작품**이다. 기술 UI보다 자연 현상의 질감·부피·느린 변화로 전달한다. 기본 답변은 한국어다.

최신 사용자 지시를 우선한다. 현재 킨텍스 프로필은 전시기획초안과 2026-10-22 사용자 확인을 따른다. **가로 12m × 세로 3m의 직선 LED 벽, 4:1 구도, 뎁스카메라, 실시간 반응 + AI 이미지·에셋의 비동기 갱신**이 기준이다. 출력 픽셀·카메라 모델·동시 관객 수·성능 목표는 미정이다. [project-context.md](references/project-context.md)에 확정 조건을, [exhibition-brief.md](references/exhibition-brief.md)에 출처·예시·충돌을 기록했다.

사용자는 제공 예시를 라넬이 추구하는 표현으로 해석하고 실제 시연은 12m 직선 벽이라고 구분했다. **설치 조건과 표현 지향을 분리**한다. 예시의 큐브·풍선·회랑을 잘못된 참고로 폐기하지 않고 재질·부피·국소 변형·스케일을 취한다. 새로 제공된 9개 영상은 [video-reference-analysis.md](references/video-reference-analysis.md), 원본 정보와 관찰 범위는 [company-video-reference-index.json](references/company-video-reference-index.json)에 있다.

## 전체 시나리오를 감독할 때

[scenario-director.md](references/scenario-director.md)를 먼저 읽고 **지원 템플릿 확인 → 배경 기획·생성 → 실제 배경 관찰 → 원본 에셋 선정 → 복제·배치와 상호작용 대상 → 효과·입자·시간 연출 → 단계별 검수**를 연결한다. 생성할 원본 종류 수, 원본별 배치 수, 입자 수를 구분한다. 실제 배경을 보기 전의 에셋 구상은 잠정안이며 본 에셋 계획으로 확정하지 않는다.

템플릿·행동·출력 형식·객체 상한은 현재 실행 환경의 카탈로그와 사전 확인 결과를 따른다. 미지원 기능을 프롬프트만으로 실행한 것처럼 기록하지 않는다. 위치·크기 등 실제 적용값과 별도 개발이 필요한 연출 제안을 구분한다. 현 EC2 Head는 구조화된 원본 에셋 계획에 감독 명세를 붙이고, 원본을 참조하는 여러 인스턴스로 UE 배치를 만든다.

EC2 API Head는 생성 실행기에 지시를 전달하고 반환 파일과 검수 근거를 읽는다. 로컬 Codex 도구나 Windows 참고 파일이 서버에도 있다고 가정하지 않는다. 서버가 실제로 읽는 간결한 지침은 [head-director-prompt.md](references/head-director-prompt.md)이며 전체 스킬을 디스크에 복사하는 것만으로 API에 주입됐다고 간주하지 않는다.

## 현재 작품의 판단 기준

1. **화면을 채우는 EARTH:** 파도·물결·이끼·숲·잎·꽃잎·안개·자연광 등의 현상이 화면 전체의 큰 구조를 만든다. 주제를 구석에 작게 장식하거나 빈 검은 공간을 주인공으로 두지 않는다.
2. **선명한 질감과 깊이:** 전경·중경·후경, 가림, 곡률·두께, 물·이끼·꽃잎의 구체적 물성이 읽혀야 한다. 밝기·블룸·패럴랙스만으로 부피를 대신하지 않는다.
3. **큰 구조와 작은 단위의 양립:** 큰 파도도, 작은 잎·물결 조각·꽃잎이 방향·밀도·가림을 공유해 만드는 큰 자연 현상도 가능하다. 작은 구성 단위를 요청하면 거대 에셋 표면에 무늬만 붙여 대신하지 않는다. 균일한 입자 벽이나 분리된 덩어리로 흐름을 가리지 않는다. 민들레 씨앗머리 같은 자연의 구형 구조 자체를 금지하지 않는다.
4. **느리지만 읽히는 변화:** 눈으로 형태를 따라갈 수 있게 전파·유영·흩날림을 설계한다. 입력 원인은 알아볼 수 있게 보여주되 즉각 폭발했다 꺼지는 효과, 빠른 컷, 화면 전체 점멸을 기본 연출로 사용하지 않는다.
5. **공유되는 흔적:** 국소 입력 → 확산 → 다중 흐름의 합류 → 잔류 → 완만한 소멸을 연결한다. 소멸은 형성보다 느리게 설계한다. 관객별 독립 장식이나 이탈 즉시 초기화는 핵심 경험을 충족하지 못한다.

검은 부분은 깊이·분리·대비를 위한 **국소 틈**이다. 넓은 암부, 거대 우주 추상, 팝아트, 네 화가의 동시 융합은 현재 기본값이 아니다. 기하학 도형·네온 사인·인공 구조물은 EARTH 출력 콘텐츠의 기본 소재에서 제외한다. 금색도 필수색이 아니다. 밝은 복도에서 읽히는 명암을 고려하되 전면 백색이나 과포화로 해결하지 않는다.

## 요청 범위를 먼저 정한다

- **전체 시나리오:** 템플릿 근거·배경 관찰·원본 에셋·인스턴스·상호작용·효과·입자·진행 단계·수용 기준을 감독 명세로 남긴다. 요청이 설계뿐이면 생성·게시를 시작하지 않는다.
- **이미지 한 장:** 콘텐츠 시안을 생성·실제 파일 검토·저장하고 끝낸다. 움직임·잔류시간·인터랙션을 정지 이미지로 검증했다고 쓰지 않는다.
- **에셋:** 배경, 개별 알파 요소, 표면 텍스처, 깊이 보조 자료, 메시/리그 중 실제 산출물을 구분한다. PNG를 메시나 측정 깊이라고 부르지 않는다.
- **움직이는 데모:** 시간 변화와 입력 원인을 검토할 결과를 만든다. 모의 입력, 2.5D, 녹화 영상과 실제 센서 런타임을 구분한다.
- **실시간 구현:** 반응 루프가 AI 응답을 기다리지 않게 하고 비동기 생성 결과는 검수 후 교체한다. 요청된 엔진·기존 프로젝트를 존중한다. 스킬 이름만으로 구현을 UE로 이전하지 않는다.
- **스킬·설계 수정:** 해당 지침과 명세만 수정한다. 문서의 일정이나 수량만으로 이미지 10종 제작, 8시간 렌더, 자동화 재개를 실행하지 않는다. 중단된 제작은 명시적 재개 요청이 있어야 재개한다.

출력 콘텐츠에는 관람객·실제 전시장·LED 외곽·설명 글자·로고를 기본으로 넣지 않는다. 요청된 공간 목업에서는 인물·바닥 반사를 스케일 참고로 사용할 수 있으며 AI 목업으로 표시한다.

## 제작과 기록

Codex에서 직접 이미지 생성·편집을 수행하면 imagegen 스킬과 가용한 내장 도구를 사용한다. EC2 Head는 등록된 생성 실행기의 계약을 따르며 이 문구로 다른 생성기·키·결제 경로를 임의 변경하지 않는다. 원본·반환 메타데이터·최종 프롬프트·입력 역할을 보존한다. 외부 유료 생성·API 전환은 스킬 수정 자체의 범위가 아니다. API 연동을 별도로 요청받으면 실제 모델·도구 지원과 비용을 확인한다. 텍스트 모델 토큰을 이미지 생성 모델 비용으로 대신 계산하지 않는다.

레퍼런스 관찰은 실제 연 파일·페이지·영상 구간에 한정한다. 기획안의 작품 설명은 기획자의 선택 이유이며 이번 실행에서 영상을 직접 본 사실이 아니다. 장면·팔레트 복제보다 입력 인과·느린 부피·스케일 등 취할 원리를 명시한다.

작품별로 [artwork-record.json](assets/artwork-record.json)을 복사해 사용한다. 실제 파일 크기·비율·경로·도구·검토 근거·입력 방식·미확정 사양을 기록한다. 미공개 모델·시드·미측정 값은 null로 둔다. 수정본에는 부모와 바꾼 점을 남기고 이전 원본·점수는 덮어쓰지 않는다.

검수는 **정지 시각 / 시간·상호작용 / 실제 센서·출력·운영**을 분리한다. 정지 시안의 높은 점수가 전시 완료를 뜻하지 않는다. 실측이 없는 FPS·지연·8시간 안정성·현장 LED 상태는 완료로 쓰지 않는다.
