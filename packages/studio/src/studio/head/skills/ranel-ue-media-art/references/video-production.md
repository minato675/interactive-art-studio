# 움직이는 데모·영상·연속 운영

영상 길이는 최신 요청과 검증할 경험에 맞춰 정한다. 기존30~60초나2분을 고정 기본값으로 쓰지 않는다. 이번 기획의8시간 루프 목표는 영상 파일 길이인지 연속 운영인지 미정이다. 하나의 시안 요청을8시간 렌더나10종 제작으로 확장하지 않는다.

## 방법과 확인 범위

| 방법 | 적합한 검토 | 한계 |
|---|---|---|
| 이미지 기반 영상 | 형태·재질·느린 시간 변화 | 새로운 관객 입력에 반응하는 런타임은 아님 |
| UE/요청된 런타임 | 독립 요소·공유 흐름·입력·잔류 | 실제 에셋·실행·센서·성능 검증 필요 |
| 레이어·상대 깊이·왜곡 | 구도와 약한2.5D움직임 프리비즈 | 독립 개체 운동·숨은 면·완전한3D복원 아님 |
| 런타임 녹화 | 입력과 시각 변화의 근거 | 실행 파일·실센서·현장검증을 녹화만으로 대체하지 않음 |

가용한 도구·입력 지원·길이 제한·비용을 확인한다. 본체 운동이 필요한데 카메라 확대만 가능한 경우 프리비즈로 표시한다. 새 도구나 외부 생성 경로로 조용히 바꾸지 않는다.

## 한 번의 경험을 관찰할 시간

관객 부재의 자율 상태, 국소 시작, 확산, 여러 흐름의 합류, 정지/퇴장 후 잔류, 느린 소멸을 볼 수 있는 구간을 선택한다. 한 화면에 여러 순간을 콜라주해 동영상으로 대신하지 않는다. 입력 위치·시각은 작품 픽셀에 덧씌우기보다 별도 테스트 로그/검수 화면에 기록한다.

느림은 영상 재생속도를 낮추는 것만으로 해결하지 않는다. 형태 유지·수명·가속·관성·전파·합류를 함께 설계한다. 짧은 클립 반복/리타이밍을 썼으면 원본 길이·반복 횟수·배속을 기록하고 순간 점프·속도 단절·의미 없는 정지 구간을 검사한다. 사람이 떠나도 흔적이 유지되는지 실제 시간축에서 확인한다.

## 파일 검수

- 실제 픽셀·FPS·길이·코덱·픽셀 포맷·오디오 유무를 읽고 전체 디코드 오류를 검사한다.
- 정상속도 연속 재생에서 느린 추적 가능성·합류·잔류·형태 연속성·전체 점멸/빠른 컷 부재를 본다. 샘플 프레임 검토와 전구간 재생을 구분한다.
- 루프 요청에는 첫/끝 위치뿐 아니라 속도·광량·가림·입자 수명·소리의 경계를 검사한다. 비슷한 첫끝 스틸만으로 루프를 통과시키지 않는다.
- 모의 입력, 실센서 입력, 무관객 자율 영상, 생성 영상의 종류를 기록한다. 고정 영상만으로 실제 입력 인과·지연을 판정하지 않는다.

## 8시간 목표를 다룰 때

운영 요청에서8시간의 의미와 단위를 확인한다: 콘텐츠의 순수 길이, 짧은 콘텐츠의 반복 재생, 실시간 연속 운용은 다른 요구다. 실제 운영에는 입력 상실·AI 갱신 실패·화면 전환·메모리/성능·복구·반복 피로를 해당 시간과 장비에서 검증한다. 짧은 데모를8시간 반복할 수 있다는 계산으로 안정성 검증을 대신하지 않는다.

최종 인계에는 실제 영상/프로젝트·사양·재생 검토 범위·루프 여부·입력 방식·남은 제한을 기록한다. 명세만 있음, 렌더 중, 실패, 파일 완료, 현장 검증을 구분한다.
