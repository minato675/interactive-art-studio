# 실시간 반응과 비동기 AI 갱신

사용자 확인 구조는 **실시간 관객 반응 + AI 이미지·에셋의 비동기 갱신**이다. 매 입력이나 매 프레임마다 이미지 API가 반환해야 반응하는 구조로 만들지 않는다. 엔진·버전·프로젝트 지침·가용 에셋을 먼저 확인하며 기존 구현을 스킬 이름만으로 UE에 이식하지 않는다. 여기의 구조는 설계 지침이고 이미 실행되는 코드가 아니다.

## 두 경로와 접점

| 경로 | 처리 | 증거 |
|---|---|---|
| 실시간 반응 | 뎁스카메라/모의 입력→좌표·유효성→자율 장에 국소 자극→전파·합류·잔류·소멸→렌더 | 입력 로그·타임스탬프·실행/녹화·프레임 시간 |
| 비동기 생성 | 장면 목표/요약→요청→반환 파일 보존→형식·시각 검수→준비된 에셋→전환 | 요청ID·원본·메타데이터·판정·적용 시각 |
| 접점 | 현재 흐름·관객 반응을 유지하며 검수된 새 자원을 적용 | 갱신 대기/실패/적용 중 반응 유지·전환 검토 |

관객 움직임은 실시간 장을 바꾸고, 필요할 때 요약된 상태·기획을 비동기 생성에 전달할 수 있다. 호출 주기·큐·취소·동시성·예산은 별도 구현 요구에 맞춰 정한다. 관객 한 번 움직일 때마다 외부 호출하지 않는다. 원시 깊이·인물 프레임의 외부 전송은 이 구조의 필수 조건으로 두지 않는다.

생성 실패·지연·검수 탈락 때는 현재 정상 자원으로 반응을 유지한다. 오래된 반환이 최신 결과를 덮어쓰지 않도록 버전/요청 관계를 확인한다. 준비 전 텍스처를 적용해 검정 프레임을 만들거나 매 교체마다 전체 흐름을 초기화하지 않는다. 레이어/장면 간 차이가 크면 단순 크로스페이드의 이중 형상도 검사한다. 전환 방식은 형태와 시간 연속성에 맞춘다.

## 실제 제작 요소

- **공간·카메라:** 사용자 확인12m×3m4:1 구도, 전후 배치와 가림, 중하단 주목점, 공유하는 안정된 시점.
- **구성 단위:** 메시·입자·표면/층 등 표현에 맞는 방식. 작은 잎의 독립 운동이 필요하면 큰 평면의 왜곡만으로 대신하지 않음.
- **재질:** 실제 렌더에서 물·이끼·꽃잎 등의 두께·투과·내부 결을 확인. AI 시안을 PBR채널로 자동 사용하지 않음.
- **움직임:** 본체와 주변 흐름의 일관성, 방향·가속·소멸의 연속성. 기본 장과 입력 자극, 리소스 교체를 분리.
- **입력:** 카메라 제공 데이터·감지 범위·가림·좌표·타임스탬프·신뢰도·상실/복귀.
- **연결:** 실제 사용한Niagara·재질·애니메이션·컨트롤러 등의 제어권과 전달 경로 명시. 이름이 같다고 값이 자동 공유된다고 가정하지 않음.

핵심 현상 하나로 재질·운동·다중 합류·잔류를 검증한 뒤 밀도·범위를 확장한다. 메시·리그를 사용하면 실제 파일과 사용 조건, 축·피벗·스케일·웨이트·임포트 결과를 검사한다. 특정 노드·플러그인·GPU 성능은 실제 환경에서 확인한다.

## 깊이와2.5D의 경계

정지 이미지+추정 상대 깊이는 약한 패럴랙스나 층별 변형에 쓸 수 있다. 흰색이 가까운지, 정렬·정규화·투명/얇은 형태의 오류를 기록한다. 이를 미터 단위 깊이·숨은 면·생물 리그·정확한 충돌로 쓰지 않는다. 시안 뷰어,2.5D프로토타입,실제3D장면의 표현 범위를 구분한다. 동적 유체·입자/장도 적절한 방법이며 모든 현상에 스켈레탈 메시를 강제하지 않는다.

## 출력·성능·완료

물리12m×3m와 실제W×H·유효 영역·프로세서 매핑을 구분한다. 출력 해상도·목표FPS·지연은 미정이면 임시/미확정으로 둔다. 최대 복잡도, 생성 대기, 새 에셋 로드/전환 중의 프레임 시간·메모리·입력 반응을 실제 장비에서 측정한다. 평균FPS만으로 순간 멈춤을 숨기지 않는다.

[quality-review.md](quality-review.md)의 단계별 검사로 자율 운동, 이동·정지·퇴장, 합류, 상실·복귀, 갱신 실패·전환을 검사한다. 실제 센서·현장 LED·밝은 복도의 중앙/측면·근거리/원거리 검증을 별도 기록한다. 예술적 느린 전파와 인식 지연은 따로 측정한다.

8시간 목표는 [video-production.md](video-production.md)의 운영 정의를 먼저 확정한 후 해당 조건에서 검사한다. 실행 파일 생성·짧은 녹화·높은 시안 점수만으로 장시간 운영이나 전시 완료를 표시하지 않는다. 요청된 프로젝트·실행 파일·시안과 실제 확인 결과를 인계한다.
